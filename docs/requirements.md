# WAV Player の要件

この文書は製品の受け入れ条件を定める。ビルドと起動は [README](../README.md)、実装上の責務は[再生設計](architecture.md)、合否の確かめ方は[試験仕様](test-specification.md)を参照する。

## 対象と配布

| 対象 | 条件 |
|---|---|
| 再生PC | 対象OSはWindows 11 25H2以降のx64。起動時にCPUのAVX2と付随命令（BMI1/BMI2、LZCNT、MOVBE、FMA、F16Cなど）、WindowsのAVX対応とXMM/YMM状態の保存を確認する。非対応なら理由を表示して終了し、SSEでの代替再生はしない。[命令セットの前提](architecture.md#命令セットの前提) |
| ビルド | Visual Studio 2026安定版とMSBuildで `.sln` と `.vcxproj` を使い、Debug/Release x64をビルドする。安定版MSVC、確定済みC++23まで、静的CRT（Debugは `/MTd`、Releaseは `/MT`）を使う。CMakeとC++26固有の機能は対象外。 |
| アプリ | 製品名はWAV Player、実行ファイルは `wavplay.exe`。音声出力はSteinberg ASIO SDK、画面はWin32の標準コントロールとシステムフォントを使う。製品名にASIO商標を使わず、UIにはロゴ、画像、独自テーマを用いない。 |

公開物はGPL-3.0-onlyの自作ソース、スクリプト、文書、設定・ビルド定義に限る。SDK、機器ドライバー、音源、実行ファイルは同梱しない。[依存とライセンス](dependencies.md)

ビルドPCの `build.cmd` はReleaseをビルドし、ローカル再生用フォルダーを作る。SDKを初回取得する場合は `-FetchSdk` を指定する。再生PCにはこのフォルダーをコピーし、`setup.cmd` で機器と音源を設定する。Visual StudioやSDKの導入は不要で、設定後は停止状態で起動する。

## 入力と出力の一致

ビットパーフェクトの保証範囲は、WAVのサンプル値から選択したASIO出力バッファーまで。音量調整、リサンプリング、ディザー、フェード、クロスフェード、エフェクトは行わない。

| 項目 | 対応範囲 |
|---|---|
| コンテナー | RIFF/WAVE、RF64。64ビットの位置・長さで4 GiBを超えるデータを扱う。 |
| 入力形式 | PCM 16/24/32 bit、IEEE Float32、および各形式の `WAVE_FORMAT_EXTENSIBLE`。 |
| Extensible PCM | 有効/格納ビット数は16/16、24/24、24/32、32/32。未使用の下位ビットに1があれば拒否する。 |
| チャンネル | ステレオは左右順を保持し、モノは同じ値を左右に出力する。 |
| レート（kHz） | 44.1、48、88.2、96、176.4、192、352.8、384。 |
| ASIO出力形式 | 整数16/24/32 bit、32 bit容器内の有効16/18/20/24 bit、Float32/64。各形式のLSB/MSBに対応する。 |

`fmt` と `data` は順不同。未知チャンクと奇数長パディングを読み飛ばし、RF64では先頭の `ds64` を用いる。必須チャンクの欠落・重複、矛盾したサイズ、破損・切断、圧縮WAV、Wave64、DSD、3チャンネル以上の入力を拒否する。

### 無損失で再生できる組み合わせ

曲中の個々の値にかかわらず、入力形式の全範囲を表現できる出力だけを許す。整数出力の有効幅とバイト配置は[ASIO契約](asio-contract.md#整数出力の有効幅と配置)に従う。

| WAV入力 | 許可するASIO出力 |
|---|---|
| PCM16 | 有効16 bit以上の整数、Float32/64 |
| PCM24（24/32を含む） | 有効24 bit以上の整数、Float32/64 |
| PCM32 | 有効32 bitの整数、Float64 |
| Float32 | Float32/64 |

停止・再開ではサンプルを加工せず、ゼロクロスも待たない。音声と無音の境界でクリックが生じることは許容する。一時停止から再開したときの欠落・重複、再生中の歪み、実装に起因する異音は不合格とする。

## 設定したデバイスでの再生

### 起動とストリームの開始

`settings.ini` の `[General] SelectedDevice` にx64 ASIOドライバーのCLSIDを手動指定する。起動時にその機器を初期化し、再初期化時を除いて終了まで保持する。キー不在・空欄・ゼロGUIDなら `NO DEVICE` と設定案内を表示し、Playを無効にする。不正なCLSID、登録の欠落、初期化失敗は理由を表示して再生を拒否する。他機器への代替、GUIや起動引数での機器変更、ASIOコントロールパネルの起動は行わない。

`[Device.{CLSID}]` の値は起動時に読み、手動編集は次回起動から適用する。数値は符号・小数点のない10進整数とする。

| キー | 未指定時 | 指定値の扱い |
|---|---|---|
| `Name` | CLSIDを表示 | 任意のUnicode表示名 |
| `OutputPair` | 1（出力1/2） | 隣接ペアの先頭番号。1始まりの奇数で指定し、機器に両チャンネルが存在することを確認する。 |
| `BufferSize` | 0と同じ | 単位はフレーム。0はバッファー作成時に現在のレートで照会した推奨幅、正の値はその幅を厳密に要求する。範囲・粒度に合わない値やドライバーの拒否では再生を始めず、別の幅に代替しない。 |
| `StartSilence` | 100 ms | 0～1000 ms。再生開始・一時停止からの再開・異レートの曲間で、最初の音声の前に指定時間をブロック単位に切り上げた無音を出す。同一レートの曲間には入れない。範囲外は再生を拒否する。 |

### 再初期化と終了

再生前にWAVのサンプルレートへ合わせる。機器が拒否したら停止する。reset・buffer-size-change通知では停止して同じドライバーを再初期化し、起動時の機器別設定を引き継ぐ。再開にはユーザーのPlayが必要となる。

変更した**サンプルレート**は再初期化・終了時に元の値への復元を試みる。**推奨バッファー幅**は通常の停止・バッファー破棄・ドライバー解放で機器が返す状態を受け入れ、復元のためにバッファーを作り直したり再始動したりしない。指定幅を保持する機器では、次回の `BufferSize=0` や同じ推奨値を使う別アプリの幅・遅延が変わり得る。推奨幅の前後差だけでは終了失敗と判定しない。[推奨バッファー幅の保持と終了時の方針](asio-contract.md#推奨バッファー幅の保持と終了時の方針)

### 画面に出す機器情報

DeviceとOutputには機器と出力ペアを表示する。Bufferでは要求設定、照会済みの能力（最小・推奨・最大・粒度）、確保できた実値と現在レートでのブロック時間を区別する。幅の検証や確保に失敗しても、その要求で確認できたレート・能力は示す。未照会・照会失敗・矛盾した能力から実値やブロック時間を推定しない。

停止後は最後の確保値であることを明示し、次のPlay・再初期化で古い能力と確保値を消す。長い機器名でもOutputを読めること、最小ウィンドウでもBufferの全情報を読めることを受け入れ条件とする。

## プレイリストと操作

### 一覧の読み込み

起動時に実行ファイル隣の `playlist.txt` を一度読む。UTF-8（BOM任意）で1行1絶対パスとし、不正なUTF-8はリスト全体のエラーとする。行末のCR/LFだけを除き、ほかの空白・順序・重複は保つ。空行と先頭が `#` の行は読み飛ばす。ローカルボリューム上のファイルだけを受理し、UNC・ネットワークドライブ、存在しないファイル、解析できないファイルは除外して件数を示す。

### 選択、再生、停止

起動時は停止状態。リストにはフルパスを表示し、ウィンドウのリサイズに追従させる。Device、Output、Buffer、リスト、操作ボタン、経過/総時間、状態は簡潔な英語で示す。Unicodeと長いパスに対応する。リピート、シャッフル、リスト編集、シーク、手動の次曲・前曲送りは対象外。

| 操作・状態 | 結果 |
|---|---|
| クリック／ダブルクリック・Enter | クリックは行を選択する。ダブルクリック・Enterは選択曲を再生する。 |
| Play/Pause・Space | 未選択なら先頭曲を再生する。一時停止はASIOのstopで位置を保ち、再開前にバッファーを充填して未再生部分から続ける。 |
| Stop・Escape | 未再生分を打ち切る。一時停止中・曲末も位置を0に戻し、選択は保持する。次のPlayは選択曲の先頭から始める。 |
| 曲間・最終曲 | 同一レートで無損失変換できる次曲へは欠落・重複・無音挿入なくつなぐ。レート切替の無音は許容する。次曲を機器で再生できなければその項目を選択して停止し、最終曲の後も停止する。 |
| アンダーラン | 直ちに停止へ移る。無音を差し込んで再生を続けない。 |

**経過/総時間**は、再生中は再生曲、停止中は選択曲を秒単位で示す。別の行を選択しても再生中の表示対象は変えない。経過は提出済みの有効PCMフレーム数で求め、開始無音では進めず、Pauseで保持し、Stopで0に戻す。曲の切替時にはその曲の位置・長さ・レートを使い、自然終端では再生を終えた曲を選択して総時間を示す。形式は `Time: m:ss / m:ss`、1時間以上は `h:mm:ss`、未取得時は `Time: --:-- / --:--`。物理DACでの聴取位置は推定しない。

### 単一起動

同一ユーザー・同一Windowsログオンセッションでは設置場所によらず1インスタンスとする。後発起動は機器の初期化前に先行ウィンドウを探し、最小化されていれば復元して前面化を要求し、正常終了する。Windowsが前面化を制限すればタスクバーで通知する。後発の引数・設定・リストは既存の再生に適用せず、自動再生もしない。先行GUIの準備は期限付きで待ち、無応答でも二重起動しない。先行プロセスの終了・異常終了後は再び起動できる。

## 設定と診断

`settings.ini` は実行ファイル隣に置き、作業ディレクトリに依存しない。手書き用の[設定例](../settings.example.ini)をコピーして使える。機器別キーの単位・既定値は[設定したデバイスでの再生](#設定したデバイスでの再生)を参照する。

### ファイルの読み込み

起動時に一度、機器・機器別設定・ウィンドウ配置を読む。UTF-8（BOM任意）、最大1 MiB、NULなし。ASCIIのセクション名・キー名・CLSIDは大小を区別せず、空白、CRLF/LF、`;` と `#` のコメントを受け付ける。読み取り失敗、不正なUTF-8、使用する既知キーの重複や不正値は設定エラーを表示し、再生を始めない。未知キーと他機器の値は保持し、再生設定に使わない。

### ウィンドウ配置の復元と保存

`[Window]` の `X`・`Y`・`Width`・`Height` は通常表示時の外枠を物理ピクセル・スクリーン座標で表す。位置は負数も可、寸法は正。既知キーがなければ標準配置を使う。1つでも指定すれば矩形の4キーはすべて必須で、`Maximized` だけの指定もエラーとなる。`Maximized` は0/1、省略時は0。復元時にモニターの作業領域とGUIの最小寸法に合わせて矩形を補正する。最小化して終了した場合も、通常矩形と最大化への復帰状態を保存する。

起動時の読み込みが成功すれば、機器が未設定でも終了時にウィンドウ状態を保存する。保存直前にファイルを再読し、`Window` の既知キーだけを更新する。機器の選択・機器別設定・未知キー・コメント・BOMと起動後の手動編集を保ち、再読した設定は再生に適用しない。同じディレクトリの一時ファイルをフラッシュしてから置換する。失敗時は既存ファイルを保ち、機器解放後にエラーを表示して非ゼロで終了する。起動時に設定エラーがあれば自動保存しない。

### 機器の診断

登録済みのCLSIDは `scripts/check-asio-drivers.ps1` でドライバーをロードせずに列挙できる。実際の初期化・能力照会・解放後の再オープンは試験用の `wavplay_tests.exe --probe-asio {CLSID}` で確認する。[実機試験の手順](test-specification.md#実機試験の手順)

## 再生経路と検証

| 境界 | 受け入れ条件 |
|---|---|
| ファイルからリングまで | 専用スレッドが `CreateFileW` と同期・キャッシュ付きの逐次 `ReadFile` で読み、出力形式への変換・モノ複製・次曲の先読みを行う。曲全体をメモリに置かない。 |
| リングの容量と配置 | 変換済み左右を固定容量の単一生産者・単一消費者（SPSC）リングで渡す。ページ単位の確保は16 MiB以下、目標は約2秒。管理領域とブロックをキャッシュラインに整列し、開始前に全ページに触れる。片側32バイト以下なら左右を同じ64バイトラインの前半・後半に置いて同時に所有・公開する。異なるブロックは別ライン、大きいチャンネルは別の整列済み平面に置く。 |
| コールバック | 通常は準備済みデータのコピー、ロックフリーなカウンター更新、閾値での通知だけを行う。メモリ確保、ロック、ディスクI/O、ログ、GUI操作をせず、停止・再初期化は制御スレッドへ依頼する。 |
| スケジューリングと電源 | アプリのスレッドはMMCSSに登録せず、ドライバースレッドの優先度・アフィニティも変更しない。再生中だけシステムの自動スリープを抑止し、画面の消灯を許す。 |

自動試験は外部フレームワーク不要のコンソールとプロジェクトの模擬ASIOで実行し、ドライバー登録を必要としない。ローカルとGitHub Actionsでビルド・試験・静的解析・AddressSanitizer・成果物監査を行い、CIの実行物は配布しない。実機の合否はx64ドライバーが提示するレート・出力型・バッファー範囲に照らして確認する。製品の挙動を機種名で分岐させない。[試験仕様](test-specification.md)

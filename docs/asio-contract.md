# 現行の PCM・Float32 再生と ASIO 契約

対象は `asio::DriverSession` が初期化して所有するドライバーを再生要求の間だけ借り（`DriverLease`）、設定した隣接出力ペアへ任意曲数のWAVをリスト順に送る経路。以下のページ番号は、[固定した SDK 2.3.4](dependencies.md) の `Steinberg ASIO SDK 2.3.pdf` を指す。API ごとの補足は取得したSDKの `common/asio.h` にある。

SDKが規定する呼び出し順・通知・表現と、製品が採る防御策・復旧方針を区別する。対応を宣告するselectorは実際の受理範囲に合わせる。SDKに復旧手順の指定がない故障は、[任意機能と未定義時の復旧](#任意機能と未定義時の復旧)に記す。

## 仕様とテストの対応

## 整数出力の有効幅と配置

固定 SDK PDF の p.33 は `Int32MSB16/18/20/24` の有効データが最下位側を占め、残りが符号拡張であると規定する。p.34 は `Int32LSB16/18/20/24` を32 bit内の右詰めとし、上位の符号拡張を同様に規定する。`LSB` と `MSB` は、いずれも最初に格納する**バイト**の順序であり、有効ビットの上位配置・下位配置とは別である。同梱 `common/asio.h` の `ASIOSTInt32LSB16` 行の「18 bit alignment」というコメントは、PDF p.34 の16 bit定義と食い違うため、この行は PDF に従う。

入力の有効幅を B、出力の有効幅を N とすると、N ≥ B の場合だけ受理し、符号付き整数値を `sample × 2^(N − B)` として格納する。浮動小数点を経由せず、丸めや下位ビットの切捨ても行わない。32 bit容器の N < 32 では N bit値の符号を上位まで延長する。Extensible 24/32 の入力は、全データの下位8 bitが0であることを読み取り開始前に検証済みの24 bit値として扱う。

例としてPCM16の負最大値・−1・正最大値の変換後の容器内の値は次のとおり。LSBは下位バイトから、MSBは上位バイトから格納する。

| 出力 | −32768 | −1 | 32767 |
|---|---|---|---|
| `Int32LSB16` / `Int32MSB16` | `FFFF8000` | `FFFFFFFF` | `00007FFF` |
| `Int32LSB18` / `Int32MSB18` | `FFFE0000` | `FFFFFFFC` | `0001FFFC` |
| `Int32LSB20` / `Int32MSB20` | `FFF80000` | `FFFFFFF0` | `0007FFF0` |
| `Int32LSB24` / `Int32MSB24` | `FF800000` | `FFFFFF00` | `007FFF00` |

例えばPCM16の−32768は `Int32LSB18` で `00 00 FE FF`、`Int32MSB18` で `FF FE 00 00` になる。試験の共有期待値は元のpacked LE値を符号付き64 bitに復元して乗算し、製品の変換器や `to_sample_format` の結果を参照せずにバイト列を作る。この期待値自身も上表の固定値で照合する。

## Float入力と浮動小数点出力

`common/asio.h` は `ASIOSTFloat32LSB/MSB` と `ASIOSTFloat64LSB/MSB` をIEEE 754の32/64 bitと定義する。整数14型と合わせた18型を `to_sample_format` で記述し、実際の受理は `find_planar_converter` の無損失性判定へ集約する。PCM16/24（Extensible 24/32を含む）はFloat32/64、PCM32はFloat64、Float32はFloat32/64を許す。Float32の有効仮数は24 bitなので、32 bit容器だからという理由でPCM32を通さない。Float32から整数への変換も、値が偶然0などであっても拒否する。

PCMは符号付き整数値を `2^(有効bit数−1)` で割った値をIEEE表現として組み立てる。例えばPCM16の−32768/0/32767はFloat32のビット列で `BF800000` / `00000000` / `3F7FFE00` になる。Float32からFloat32は全ビットを保つ。Float64への拡張は通常値の指数へ896を足し、仮数を29 bit左へ移す。subnormalは整数で正規化し、符号付きゼロを保持する。NaNは符号と仮数部23 bit（quiet/signalingビットとペイロード）を同じ29 bit移動で保持し、無限大も保つ。これらは演算でNaNをquiet化せず、丸めモード・FTZ/DAZ・例外フラグを変えない製品方針である。NaNの固定例 `7F800001` はFloat64の `7FF0000020000000`、`FFC12345` は `FFF82468A0000000` となる。

WAVの通常Float32はfmt16を互換受理し、WAVEFORMATEXのfmt18では `cbSize=0` を検査する。IEEE_FLOATの32 bit・blockAlign・byteRateは [Microsoft WAVEFORMATEX](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex) に従う。ExtensibleはIEEE_FLOAT SubFormat、有効/格納32/32、PCMと同じモノ/ステレオのマスク制約で扱う。

[EBU Tech 3285 Supplement 1 Appendix A](https://tech.ebu.ch/files/live/sites/tech/files/shared/tech/tech3285s1.pdf) が転載するRIFF仕様では、非PCMのWAVEに `fact` を必要としている。本製品は非圧縮Float32のデータ長からフレーム数を確定できるため、互換方針として欠落も受理する。存在する場合は4バイト以上・単一・宣言フレーム数の一致を検査する。RF64ではfact値が `0xFFFFFFFF` のときだけ `ds64.sampleCount` を使い、通常値なら32 bit宣言値を使う（[RF64の解釈](architecture.md#コンテナーと64ビット位置)）。fmt/data/factは順序に依存せず、奇数長パディングと範囲は共通RIFF/RF64検査を使う。PCMに対するfactの既存の扱いは変えない。検証後の再開ではfmt/fact/ds64を読み直さず、保護した同一ファイルの独立カーソルを開く。

## 推奨バッファー幅の保持と終了時の方針

製品は終了・再初期化時に推奨バッファー幅を自動復元しない。通常の停止・バッファー破棄・ドライバー解放は完了し、推奨幅を戻すための追加のバッファー作成やストリーム開始は行わない。元の値への復元を試みる対象は、製品が変更したサンプルレートである。[製品の要求](requirements.md#設定したデバイスでの再生)

固定SDK 2.3.4の `common/asio.h` の `ASIOGetBufferSize` は、推奨幅を性能・ハードウェア条件に適したサイズとして返す。工場出荷値やセッション終了時に戻る値とは定義していない。`ASIOCreateBuffers` は対応範囲内の幅を選び、`ASIODisposeBuffers` は停止とバッファー解放を行う。推奨幅の保存・巻戻しは規定されず、`IASIO` と標準の `future` selector に推奨幅だけを設定・復元するAPIはない。

実装では `playback/segment.cpp` が停止・callback切離し後に `disposeBuffers` を呼ぶ。`asio/driver_session.cpp` の `DriverSession::restore_and_release` は `original_rate_` だけを保持し、必要なら元レートを設定・読み戻してから、失敗時もドライバー参照を解放する。元の推奨幅の記録や、終了時のバッファー再作成は行わない。`control/playback_controller.cpp` はこの解放後にWindow設定を保存する。推奨幅の照会結果は、バッファーや再生が終了後も生きていることを意味しない。

製品の `BufferSize=0`／未設定はバッファー作成時の実レートで照会した推奨幅を選び、起動時の値や工場出荷値へ固定しない。ドライバーが指定幅を推奨値として保持する場合、以後の設定0での再生や同じドライバーの推奨幅を使う後続アプリの幅・遅延に影響し得る。正の `BufferSize` を指定した製品は、その値を現在のレートの範囲・粒度で再検証して使用し、別の幅へ代替しない。

終了前後で推奨幅が違うことだけを失敗とはしない。ドライバーが元レートへの復帰等で推奨幅を戻す場合も許容し、指定幅が必ず残ることは要求しない。試験条件を揃えるために別の診断や設定変更を行った場合は、製品終了直後の状態と分けて記録する。前後の幅の一致や、復元用診断の実行を製品の正常終了の条件にはしない。幅を戻すためにストリームを開始すると追加のcallback・待機・失敗経路を生むため、終了処理へ組み込まない。`createBuffers` と `disposeBuffers` による推奨幅の変化もドライバー共通の保証にはしない。[試験での判定](test-specification.md#リリース全体の確認)

## 任意機能と未定義時の復旧

- **任意機能。** Windows 上の同期コピーと通常の `bufferSwitch` を使う。TimeInfo・TimeCode は宣告しない。`outputReady` は採用したホストが出力完成を通知して遅延を短縮する仕組みで、現行経路は登録した通常コールバックの復帰時に出力を渡す（pp. 8, 21, 32）。その場での再同期・遅延の再取得・バッファー幅変更も受理しない。照会には 0 を返し、ドライバーが直接構成変更を知らせた場合は停止する。バッファー幅変更については PDF が許す拒否応答と、ヘッダーの旧実装向け注記の双方に合う。
- **過大な出力遅延。** SDK は `getLatencies` の値に上限を定めていない。一時停止と終端は報告遅延の分だけ排出を待つため、ホスト方針として現在のレートで2秒を超える報告は開始前に拒否し、バッファーを解放する。
- **開始前の読み込み失敗。** 初期充填の後、B の事前充填までに生産者が失敗した場合は、開始せずに `read_error` で終える。ドライバー故障とは区別する。
- **開始後の通知途絶。** SDK は `start()` 自体の所要時間に上限を定めていない。成功して戻った後の監視窓はホスト方針として「制御の起床周期と4ブロック時間の長い方」とし（起床周期は1秒から20 msと1ブロック時間を引いた値、下限0.5秒。47 ms以下のブロックで933～979 ms。ブロックが長いほど短くなり、約196 ms以上のブロックでは窓が4ブロック時間で決まる）、窓全体で切替がなければ `driver_error` で stop・dispose に進む。状態通知があれば直ちに起床する。ドライバー関数自体が復帰しない状況で、別スレッドから解放を強行する機能はない。
- **一時停止位置。** ホスト方針として、ブロック境界で PCM の供給を止め、提出済みの有効フレームを通常の終端と同じ手順で排出してから stop する。停止要求時点のハードウェア位置は推測せず、`getSamplePosition` が全0・未対応でも同じ処理を使う。pause 完了には排出時間がかかる。最終ブロックが提出済みなら通常終端を優先する。stop・dispose までの通知と、読み込みスレッド終了時の失敗を確認してから位置を確定する。模擬試験では、stop で未再生分を捨てる独立した出力キューの実再生列を停止前後で照合する。停止・再開時の波形と無音の不連続によるクリックは、原音を保つ[製品方針](requirements.md#入力と出力の一致)として許容する。
- **不正な出力。** 作成に成功した4つの半面は、すべて非 NULL、相互に非重複で、要求バイト数の全域が書き込み可能であることを充填前に調べる。末尾だけが読み取り専用の範囲でも拒否する。ページの確認は Windows 上の防御策で、ドライバーが以後もその割り当てを維持する責任は残る。最初の切替が来ない場合に備え、A は開始前に無音にする。[VirtualQuery](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualquery)
- **部分失敗。** `createBuffers` が失敗したときに部分的な割り当てが残るかは規定されていない。出力アドレスが返っていればそこに書かず、一度 dispose を試す。`ASE_InvalidMode` は既に解放済みの場合と両立するため元の作成エラーを残す。それ以外の解放失敗は呼び出し元に伝える。アドレスが一つも返っていない場合は開始せず、作成エラーを返す。SDK のサンプルドライバー自身も作成途中の失敗を片付ける（`driver/asiosample/asiosmpl.cpp`）。
- **故障の文言。** 回復しないドライバー関数の `ASIOError`（`asio::throw_if_error` を通る失敗）は、操作名（例 `ASIO start failed`）を固定の接頭辞とし、列挙子名と10進値を続けた `std::runtime_error`（`ASIO start failed: ASE_HWMalfunction (-999)`）にする。定義外の値は `Unknown` と値で示す。`ASE_InvalidMode`・`ASE_NoClock`・`ASE_HWMalfunction` などの区別を実機の故障報告に残すためで、文字列は制御スレッドだけで整数の整形により作る。先の呼び出しの失敗後に後の呼び出しも失敗した文言（`ASIO stop failed after start error`、`ASIO disposeBuffers failed after createBuffers error`）は、値が後の stop・`disposeBuffers` のものであることを文言の先頭で示す。先の start・`createBuffers` の失敗は型・文言・値を持つ入れ子の原因として保持する。start・stop・dispose がすべて失敗した場合も3段すべてを保持し、GUIのエラー表示から追跡できる。共通の `throw_if_error` が例外処理中の失敗だけに現在の例外を入れ子にするため、通常の失敗に空の原因は付けない。過負荷能力の照会（`ASIO overload inquiry failed`）と元レート復元の `setSampleRate`（`Failed to restore original ASIO sample rate: setSampleRate failed`）も同じ境界を使い、ASIOの列挙子名と値を残す。値を付けないのは、戻り値が `ASIOBool` の `init`（`getErrorMessage` の文があれば付ける）と、成功した応答の値の検証（例 `Invalid ASIO output latency`）である。単曲で設定ペアを拒否する文言は、ペアが出力数の範囲内なら左右の型の列挙子名を末尾に付ける（`…for this WAV: ASIOSTInt16LSB/ASIOSTInt24LSB`）。範囲外のペアはチャンネル番号で照会せず、従来の文言のままとする。型名は注記にすぎず、出力数や型の再照会が `ASE_OK` 以外を返すか故障した場合も従来の文言のまま拒否する。
- **レート設定の部分失敗。** 設定の前に元レートを記録する。初回設定がエラーでも、機器側でクロックが切り替わったか、実レートを確認できないときは解放時に復元を試みる。拒否直後に元レートのままと確認できれば、その後の外部変更には書き戻さない。
- **借用の境界。** クロック喪失、不正な半面番号、出力順序の破綻では次曲へ自動移行しない。reset の 1 は要求を受け取ったことを示す。reset・buffer-size-changeは `reinitialize_required` として現在の再生を終え、コントローラーが停止・元レート復元・解放後に同じセッションの機器を再初期化して停止待機する。同期APIだけでは再初期化も再開も行わない。再生中に同じ STA のウィンドウ処理から `DriverSession::close()`・`reopen()` が呼ばれた場合は、呼び出し元にエラーを返し、再生が戻るまで機器を保持する。再生中に `DriverSession` 自体を破棄することは契約違反とする。バッファーとコールバックが生きたままドライバーと STA を解放すると、再生側が破棄済みのセッションへ書き込むため、デストラクターは標準エラー（Win32の標準エラーハンドルがある場合。CRTのstdioは使わない）とデバッガー出力に1行を出して `std::terminate()` で直ちに終了する。元レートの復元と解放は `DriverSession` が担う。解放失敗などの故障では自動回復せず、所有者が旧ドライバーとコールバックを終了させてから新しい再生要求を用意する。

`outputReady` を呼ぶと、毎回のコールバックの中でドライバー関数を1回呼ぶことになる。現行のコールバックを準備済みデータのコピー・カウンター更新・閾値での通知に限る[要求](requirements.md#再生経路と検証)に従い、製品では呼ばない。固定SDKの `common/asio.h` が説明する利点は、ドライバーが次に再生するDMAバッファーへホストのデータを直接変換でき、出力遅延が1ブロック減ることであり、期限までの余裕を増やすことではない。TimeInfoやその場での再同期・遅延の再取得・バッファー幅変更も、上記の受理範囲に従う。

ユーザーの Stop はホスト側の打切り操作であり、一時停止・正常終端の排出待ちを行わず、制御スレッドで `stop`・コールバックの切離し・`disposeBuffers` を行う。読み込みスレッドの終了まで確認して位置を0にし、次の Play で先頭から新しいバッファーを作る。追加callbackがなくても既存イベントで制御側を起こす。Stopでも初期化済みのドライバーは保持し、故障の解除や再初期化は行わない。模擬 DAC では打切り時の未再生PCM破棄を許し、次のPlayの全フレームを元WAVと照合する。

模擬試験は [試験仕様](test-specification.md) のローカル検証で実行する。模擬時刻と出力バッファーの一致までが自動判定の範囲で、実機の物理出力・USB遅延・ドライバーの復帰は [実機試験の手順](test-specification.md#実機試験の手順)で別に確認する。

再生終了を待つ制御スレッドが COM STA の場合は、停止イベントとウィンドウメッセージを一緒に待つ。ドライバーのウィンドウがメッセージを受けても、別の待機中要求などから停止イベントが通知されても、コールバック監視の期限は延長しない。期限切れは未消費のイベントより優先して返し、呼出し側は再生状態を別に確認する。ただし期限前にキューへ投稿された `WM_QUIT` は、メッセージ処理の上限で後回しになっても期限切れより優先し、終了として扱う（`PostQuitMessage` の終了フラグは、Windows の規則どおり投稿済みのメッセージがなくなった時点で届いたものとする）。`WM_QUIT` を受けた場合は外側のループへ終了コードを引き継ぎ、制御側で再生を終了する。終了操作であって故障ではないため、再生要求はユーザーの Stop と同じ `stopped` で終える。[Windows の STA メッセージ処理](https://learn.microsoft.com/en-us/windows/win32/com/single-threaded-apartments)

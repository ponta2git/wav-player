## クロックと出力ペア

### サンプルレート

SDK では、非対応レートの能力照会は `ASE_NoClock`、外部クロックによる設定拒否は `ASE_InvalidMode`、クロック喪失時の変更通知はレート 0 となる。`asio.h` の `kAsioResetRequest` は、再構成を要する機器を Exit・Init で開き直す例を示す。

- **開始時**は、曲と実レートが異なればバッファー作成前に `canSampleRate` → `setSampleRate` → `getSampleRate` の順で確認する。能力照会中は旧クロックの再通知を許し、設定直前に期待レートを切り替える。
- **異レートの曲間**では旧区間を停止し、バッファー解放・元レート復元・ドライバー解放を済ませる。再初期化した機器で過負荷通知能力と実レートを調べ、必要なら同じ順序でレートを合わせる。
- **レート拒否**は能力照会の `ASE_NoClock`、設定の `ASE_NoClock`・`ASE_InvalidMode`、読み戻したクロックの無効・不一致。曲選択を伴わない要求の先頭は `first_rate_rejected`、プレイリストの項目や異レートの次曲は `next_rate_rejected` となる。競合した故障は拒否より優先する。

セッションは初回設定の前に元レートを記録する。設定エラーでも実レートが変化または不明なら、解放時に設定・読み戻しで復元を試す。エラー直後に元のままと確認できたら、その後の外部変更には書き戻さない。復元に失敗してもドライバー参照は解放する。[DriverSession の実装](../src/wavplay/asio/driver_session.cpp)

### 出力の選択と割り当て

設定の `OutputPair` は1始まりの奇数、ASIO のチャンネル番号は0始まり。まず出力数を調べ、範囲内の左右だけに `getChannelInfo` を呼ぶ。両方が同じ無損失出力形式であることを求め、`createBuffers` 後はレート・左右の型・有効状態・要求したチャンネル番号を再確認する。

充填前に左右の A/B 全4領域が非 NULL で互いに重ならないことを確かめ、各領域の要求バイト数すべてに書き込めるかを Windows のページ単位で調べる。末尾だけが読み取り専用でも拒否する。以降は解放までドライバーが割り当てを維持する。[VirtualQuery](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualquery)

## 推奨バッファー幅の保持と終了時の方針

`getBufferSize` の推奨幅はドライバーが現在の条件に適すると報告するフレーム数である。`createBuffers` で対応する幅を選び、`disposeBuffers` で解放する。SDK は推奨幅の保存・巻き戻しを定めておらず、`IASIO` と標準の `future` selector に推奨値だけを設定・復元する API はない。

- **作成時**に、確定した実レートで最小・最大・推奨・粒度を照会する。`BufferSize=0` または未設定ならその時点の推奨幅を使う。正の指定は範囲と粒度を満たした場合だけそのまま使う。
- **終了・再初期化時**の自動復元は、セッションが変更したサンプルレートに限る。推奨幅のためのバッファー再作成や再生は、追加のコールバック・待機・失敗経路を生むため行わない。終了時のウィンドウ設定は機器解放後に保存する。
- **終了後**に推奨幅が残るか戻るかはドライバーによる。保持されれば、次回の設定 0 や後続アプリの推奨幅・遅延に影響し得る。幅の変化だけではバッファーの残存や終了失敗とは判定できない。製品終了直後の値は後続の診断・設定変更と分けて記録する。[製品要件](requirements.md#設定したデバイスでの再生)・[終了後の判定](test-specification.md#リリース全体の確認)

## 整数出力の有効幅と配置

`to_sample_format` が扱う整数出力は、`Int16`・packed `Int24`・`Int32` と、32 bit 容器で有効幅が 16/18/20/24 bit の4種。それぞれに LSB/MSB があり、計14型となる。`LSB` / `MSB` はメモリへ先に置く**バイト**を示す。有効幅が容器より小さい8型では、どちらのバイト順でも有効値を右詰めにして上位を符号拡張する（SDK pp. 33–34）。`asio.h` の `ASIOSTInt32LSB16` に付いた「18 bit alignment」というコメントは p. 34 の16 bit定義と食い違うため、PDFに従う。

再生入口は `find_planar_converter` で入力・出力の組を判定する。入力の有効幅を B、出力の有効幅を N とすると、整数出力は N ≥ B の場合に受理し、符号付き値を `sample × 2^(N − B)` で格納する。整数演算だけで PCM32 の下位まで保持する。Extensible 24/32 は全データの下位8 bit が 0 であることを再生前に検証し、有効幅 24 bit として扱う。

| PCM16 からの出力（32 bit 容器内の値） | −32768 | −1 | 32767 |
|---|---|---|---|
| `Int32LSB16` / `Int32MSB16` | `FFFF8000` | `FFFFFFFF` | `00007FFF` |
| `Int32LSB18` / `Int32MSB18` | `FFFE0000` | `FFFFFFFC` | `0001FFFC` |
| `Int32LSB20` / `Int32MSB20` | `FFF80000` | `FFFFFFF0` | `0007FFF0` |
| `Int32LSB24` / `Int32MSB24` | `FF800000` | `FFFFFF00` | `007FFF00` |

例えば −32768 の出力列は `Int32LSB18` で `00 00 FE FF`、`Int32MSB18` で `FF FE 00 00`。試験は packed LE 入力を符号付き64 bitに復元して期待列を作る。この計算は製品の変換器・型対応表から独立し、上表の固定値でも照合する。

## Float入力と浮動小数点出力

SDK の `ASIOSTFloat32LSB/MSB` と `ASIOSTFloat64LSB/MSB` は IEEE 754 の32/64 bit。整数14型と合わせた18型について、無損失で表せる組だけを受理する。Float32 の有効精度は24 bitである。[入出力の対応表](requirements.md#入力と出力の一致)

| 変換 | 出力ビットの契約 |
|---|---|
| PCM16/24 → Float32/64、PCM32 → Float64 | `sample / 2^(B − 1)` の IEEE 表現を整数演算で組み立てる。PCM16 の −32768・0・32767 は Float32 で `BF800000`・`00000000`・`3F7FFE00`。PCM32 → Float32 は拒否する |
| Float32 → Float32 | 符号・指数・仮数の全32 bitを保存する。Float32 入力の整数出力は値にかかわらず拒否する |
| Float32 → Float64 | 正規数では指数フィールドに896を足し、仮数部を29 bit左へ移す。非正規数は整数で正規化する。符号付きゼロと無限大、NaNの符号・quiet/signaling ビット・ペイロードを保存する |

NaN の固定例は `7F800001` → `7FF0000020000000`、`FFC12345` → `FFF82468A0000000`。これらの変換では NaN を quiet 化せず、丸めモード・FTZ/DAZ・例外フラグを変えない。

WAV 入力の形式は WAVEFORMATEX に従う。製品は16バイトの IEEE_FLOAT `fmt` も互換受理し、RIFF が非 PCM に要求する `fact` の欠落は `data` 長から補える場合に許容する。`fmt`・`fact` の検査、RF64 の64 bit値への置換、再開カーソルの扱いは媒体層の設計を参照する。[WAVEFORMATEX](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex)・[EBU Tech 3285 Supplement 1 Appendix A](https://tech.ebu.ch/files/live/sites/tech/files/shared/tech/tech3285s1.pdf)・[コンテナーと64ビット位置](architecture.md#コンテナーと64ビット位置)

## 開始から停止まで

SDK では `start` 前に B（半面1）を充填し、最初の切替は A（半面0）である。ハードウェア始動前に複数の切替が届く場合もある（pp. 8, 13–14）。製品は最初の切替が来ない場合に備え、A を先に無音にする。

各区間の開始無音は `StartSilence`（既定100 ms）を整数ブロックに切り上げ、B から数える。0なら B に先頭の音声を置く。同一レートで連続再生する曲間は無音を挟まず、異レートで開始する各区間には開始無音を付ける。リングの初期充填後、B の充填までに読み込み失敗が分かったときは、開始せず `read_error` で終える。

作成後の `getLatencies` が返す出力遅延は、切替で指定された半面が鳴り始めるまでのフレーム数。SDK に上限はない。製品は負値と現在レートで2秒を超える値を開始前に拒否し、バッファーを解放する。

| 終了の契機 | 音声と位置の扱い |
|---|---|
| 正常終端 | 末尾の有効フレームと出力遅延分を排出する。最後のブロックのゼロ埋めを曲の長さに算入しない |
| 一時停止 | ブロック境界で追加供給を止め、提出済みフレームを同じ手順で排出する。最終ブロックを提出済みなら終端を優先する。`getSamplePosition` が未対応・全0でも処理は同じで、停止・解放中の通知と読み込みスレッドの終了結果を確認してから位置を確定する |
| ユーザーの Stop | イベントで制御側を起こし、追加の切替や排出を待たずに停止・解放する。未再生分の破棄を許し、読み込みスレッド終了後に位置を0に戻す。次の Play で新しくバッファーを作る。初期化済みドライバーを保持するので、Stop で故障を解除したり再初期化したりはしない |

排出では報告遅延に少なくとも B の1ブロックを見込み、開始時の切替で1ブロックを超えて先行提出したフレームを加える。先行した無音も数える。これで複数の先行要求とブロック未満の遅延端数が重なっても末尾を送れる。報告値が全先行量を含む場合は待ちが長くなる。

一時停止・正常終端では、報告より深いキューを見込み、排出後も無音を返して**実時間で2ブロック分**待つ。この間の再生位置は進めない。待機・`stop`・`disposeBuffers` 中のドロップアウトも `underrun` で次曲を止める。Pause/Stop と再開時の波形不連続によるクリックは許容する。[音声を加工しない方針](requirements.md#入力と出力の一致)

## 任意機能と未定義時の復旧

### 通知の照会と直接通知

`kAsioSelectorSupported` は指定された selector の対応可否を返す。直接通知での返答と、実際に再生が続くかは別に扱う（SDK pp. 29–32）。

| selector | 対応照会 | 直接通知の返答と製品の動作 |
|---|---|---|
| `kAsioSelectorSupported` / `kAsioEngineVersion` | 1 | それぞれ指定した selector の対応可否 / エンジン版 2 |
| `kAsioResetRequest` | 1 | 1。要求を受領し、`reinitialize_required` で現在の再生を終える |
| `kAsioBufferSizeChange` | 0 | 0。動作中の幅変更を拒否し、`reinitialize_required` とする。PDF が許す拒否応答、`asio.h` の旧実装向け注記と整合する |
| `kAsioResyncRequest` / `kAsioLatenciesChanged` | 0 | 0。その場での再同期・再照会は行わず、`driver_error` で停止する |
| `kAsioOverload` | 1 | 1。報告された脱落を `underrun` として記録する |
| TimeInfo / TimeCode、その他の未対応 selector | 0 | 0。TimeInfo コールバックは登録しない |

再生要求の初めと再初期化時に `future(kAsioCanReportOverload)` を照会する。`ASE_SUCCESS` はドライバーが過負荷を検出して通知するという SDK の応答。旧ドライバーの `ASE_OK`・`ASE_InvalidParameter`・`ASE_NotPresent` も未対応として許容する。ホスト自身の空リング、読み取り失敗、出力への競合書き込みは個別に検出する。コピー中に同じ半面へ再入した場合も、反対の半面へ並行した切替が来た場合も `underrun` とし、リングを二重消費しない。

製品は Windows の通常の `bufferSwitch` 内で同期コピーし、コールバック復帰時に出力を渡す。`outputReady` は、次の DMA バッファーへドライバーが直ちに変換できる場合に出力遅延を1ブロック減らす任意の API である（SDK pp. 8, 21）。製品のコールバックをコピー・カウンター更新・必要な通知に限るため、ここからドライバー関数は呼ばない。[再生経路の要件](requirements.md#再生経路と検証)

### 切替の監視と STA の待機

SDK は `start` 自体の所要時間を定めていない。成功して戻った後は、窓全体で新しい切替がなければ `driver_error` とし、停止・解放に進む。ドライバー関数自体が戻らない場合に別スレッドから強制解放する方式は採らない。

- 制御の起床周期は `max(500 ms, 1000 ms − 20 ms − 1ブロック時間)`。監視窓はこの周期と4ブロック時間の長い方で、各ブロック時間は対象ブロック数の合計をミリ秒に切り上げる。
- 1ブロックが47 ms以下なら起床周期は933～979 ms。約196 ms以上では4ブロック時間が監視窓を決める。状態通知で直ちに起床しても、無関係なイベントやウィンドウメッセージで監視期限を延ばさない。
- 制御スレッドが COM STA なら、停止イベントとウィンドウメッセージを一緒に待つ。通常は期限切れを未消費イベントより優先し、再生状態を別に確認する。期限前にキューへ投稿済みの `WM_QUIT` は処理の上限で残っていても優先する。`PostQuitMessage` の終了フラグは投稿済みメッセージが尽きた時点で届く。終了コードを外側のループへ引き継ぎ、再生要求はユーザーの Stop と同じ `stopped` で終える。[Windows の STA メッセージ処理](https://learn.microsoft.com/en-us/windows/win32/com/single-threaded-apartments)

### 部分失敗とセッションの寿命

- **作成失敗時**は部分割り当てが残る場合がある。残存時の処理は SDK に規定がない。`createBuffers` がアドレスを1つでも返せば書き込まず、一度だけ `disposeBuffers` を試す。成功・`ASE_InvalidMode`（解放済みと両立）なら元の作成エラーを返し、他の解放エラーは作成エラーとともに伝える。アドレスが皆無なら作成エラーだけを返す。SDK のサンプル `driver/asiosample/asiosmpl.cpp` は作成途中の失敗を自ら片付ける。
- **開始・停止時**は `start` が失敗しても切替を開始した可能性を考慮し、`stop` を試す。SDK は正常な `stop` の復帰後に新たな切替を呼ばないと定める。製品はコールバックを切り離し、進行中の書き込みを待って解放する。停止失敗で出力がまだ結び付いていた場合は両面を無音にし、`disposeBuffers` の暗黙の停止にも備える。[区間の後始末](../src/wavplay/playback/segment.cpp)
- **再初期化**が必要な場合、同期再生 API は reset・幅変更に `reinitialize_required` を返す。コントローラーが停止・元レート復元・解放後に同じ機器を再初期化し、成功時は停止状態で次の Play を待つ。クロック喪失・不正な半面番号・出力順序の破綻・解放失敗では次曲へ進まず、所有者が旧機器とコールバックを終了させて新しい要求を用意する。[コントローラー](../src/wavplay/control/playback_controller.cpp)
- **借用中**に同じ STA のウィンドウ処理から呼ばれた `DriverSession::close()`・`reopen()` はエラーを返して機器を保持する。借用中に `DriverSession` 自体を破棄するのは契約違反である。生きたコールバックが解放済みセッションを使うのを防ぐため、デバッガーと利用可能な Win32 標準エラーハンドルへ1行出力し、`std::terminate()` で終了する。

試験では、停止後の遅れた非同期切替と `disposeBuffers` 内の同期切替を区別する。別スレッドでコピーを止めたまま `detach` を呼び、完了まで解放が待つことも確かめる。

### エラーの表示

`asio::throw_if_error` を通る失敗は、制御スレッドで操作名・`ASIOError` の列挙子名・10進値を並べた `std::runtime_error` にする。例は `ASIO start failed: ASE_HWMalfunction (-999)`。定義外の値は `Unknown` と数値で示す。

- 過負荷照会の `ASIO overload inquiry failed`、元レート復元時の `Failed to restore original ASIO sample rate: setSampleRate failed` にも同じ形式を使う。`ASIOBool` を返す `init` は利用できれば `getErrorMessage` の文を付ける。成功した呼び出しの値検証（例 `Invalid ASIO output latency`）には ASIO エラー値を付けない。
- 単曲の出力ペアを拒否するとき、範囲内の左右の型を再照会できれば `…for this WAV: ASIOSTInt16LSB/ASIOSTInt24LSB` のように追記する。範囲外の番号は問い合わせず、出力数・型の再照会に失敗した場合も元の拒否理由を保つ。

後始末も失敗したときは最後の操作名と値を外側に置き、先の例外の型・文言・値を原因に残す。開始・停止・解放がすべて失敗した場合は GUI から3段ともたどれる。単独の失敗には空の原因を付けない。

| 後始末も失敗した条件 | 外側の操作名 |
|---|---|
| `createBuffers` の失敗後、部分割り当ての解放も失敗 | `ASIO disposeBuffers failed after createBuffers error` |
| `start` の失敗後、`stop` も失敗 | `ASIO stop failed after start error` |
| バッファーの作成成功後、準備・開始・停止などの例外処理中に解放も失敗 | `ASIO disposeBuffers failed during cleanup` |

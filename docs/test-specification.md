# WAV Player の試験仕様

変更の受け入れに使う検証項目、入力、期待結果を示す。結果には対象コミットと実行物のハッシュを対応付け、項目ごとに「合格」「失敗」「未実施」を記録する。ここに試験項目があること自体は、過去の実行や合格を示さない。

## 判定の順序

| 確認すること | 実行者と環境 | 実行・判定の入口 |
|---|---|---|
| ビルド設定・成果物 | 開発者またはCI。Windows x64、Visual Studio、SDK | [ビルドとソースの監査](#ビルドとソースの監査)。開発環境と生成コードを検査する |
| 音声データ・再生制御 | 開発者またはCI。同じビルドPC、実機ドライバー不要 | [ドライバーなしで判定する項目](#ドライバーなしで判定する項目)。模擬出力を独立した期待値と照合する |
| GUIと制御の接続 | 開発者またはCI。Windows、実際のWin32コントロール、模擬ASIO | [GUIの接続](#guiの接続)。入力、表示、解放と代表形式の出力を確認する |
| 物理出力と利用者操作 | 試験者。対象OSとx64 ASIO機器 | [実機試験の手順](#実機試験の手順)。画面・操作・聴感・測定の観測を記録する |
| ソース公開・再生用フォルダー | 公開候補を確認する担当者。ビルドPCと移動先の再生環境 | [公開候補とローカル再生用フォルダーの確認](#公開候補とローカル再生用フォルダーの確認)。許可リストと移動後の起動を確認する |

### ローカルとCIの全検証

[README](../README.md) のビルド環境を用意し、リポジトリのルートで次を実行する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1 -Analyze -IncludeASan
```

1. 共有ライブラリと製品・試験の両EXEについて、登録と評価済みビルド設定を監査する。
2. Debug・Release x64を静的解析付きで再ビルドし、Debug-ASanもビルドする。生成物は構成ごとの基準で監査する。
3. ReleaseとDebug-ASanで試験群を実行する。Debugの実行時検査はDebug-ASanに含まれる。ソリューションのビルドやSDKヘッダーの検査だけでは再生機能の合否は決まらない。

ソース公開時のGitHub Actionsは `scripts/ci.ps1` から `check-public-source.ps1 -Tracked`、ソース公開と構成検査のPowerShell回帰試験、SDKの取得・検査、上記の全検証、再生フォルダー設定のPowerShell回帰試験を実行する。

手動で `release_only` を選ぶと、`verify.ps1 -Configuration Release` でRelease限定の診断を行う。実行名とログにモードを示し、静的解析とDebug-ASanは「未実施」とする。全検証の合格には全構成での実行が必要。

CIの詳細ログはrunnerの一時領域で処理する。公開ログは合否、試験・ケース名、ソースのファイル名と行番号、数値の期待値と実測値に限る。既知の例外型は許可リストの型名だけを再構成し、GUI送信失敗は固定の識別子・メッセージ番号・Win32エラー番号だけを表示する。例外の詳細、ローカルパス、実行物は公開せず、実行物をartifactやReleaseへアップロードしない。

## ドライバーなしで判定する項目

PCM16・24・32とFloat32の入力、対応するASIO出力型、SDKの規定・任意機能・ホストの故障時方針を、製品と同じ経路で確かめる。各APIの規定と試験の対応を確認する。[ASIO契約の照合表](asio-contract.md)

Releaseでは `out/x64/Release/` の `wavplay_tests.exe --list` で群名を調べ、`wavplay_tests.exe --suite 群名` で個別に実行する。実行対象のソースは登録表からたどれる。[試験群の登録表](../tests/wavplay_tests/suites/suites.h)

**失敗時の読み方**

- 引数なしの実行は群ごとに子プロセスを使い、既定で最大4群を並行実行する。PASS・FAIL・TIMEOUT・CRASHを集計し、1件でも失敗なら非ゼロで終了する。通常の失敗はケース名、期待値・実測値、ファイルと行を示す。
- `run_timed` と再生用の監視が検出した停止、`std::terminate`・`abort`・CRTの不正パラメーター、DebugのCRT報告、AddressSanitizerが扱わない未処理例外は群とケースを示す。ケース単位の監視がない停止は群の上限で終了し、fail-fast（0xC0000409）やASanの報告（86）と同様に群だけを示す。後続の群は続行する。
- 試験の待機上限はReleaseを基準にDebugで3倍、ASanで4倍とする。この倍率は製品の時間設定には適用しない。

**変更箇所に対応する試験**

- WAV・RF64の入力、形式の拒否、サンプルの一致は[読み取りと形式変換](test-playback.md#wavrf64の読み取りと形式変換)、起動時の曲順や設定保存は[プレイリストと設定の入出力](test-playback.md#プレイリストと設定の入出力)。
- 機器の照会・出力ペア・異レート再生は[模擬ASIOの初期化・出力・レート切替](test-playback.md#模擬asioの初期化出力レート切替)、連続した波形の境界は[リング・曲間・開始無音と終端](test-playback.md#リング曲間開始無音と終端)。
- 模擬DACで停止前後の有効フレームを比べるときは[Pause・Stop・再開時の出力](test-playback.md#pausestop再開時の出力)。制御要求と通知を競合させるときは[非同期受付・再初期化・終了](test-playback.md#非同期受付再初期化終了)。

## Win32 GUIの自動試験

### GUIの接続

`--suite player_window` は製品と同じ `run_player_window` を独立UIスレッドで動かし、登録不要の模擬ASIOと実際のWin32コントロールを使う。GUIと制御層は入力・出力形式で分岐しないため、形式・出力型・チャンネル数ごとの変換と操作の一致は下位層の試験群（`wav_header`・`wav_reader`・`prefetch_ring`・`output_format`・`segment`、模擬DACを使う `track_player`・`track_source_formats`・`track_output_types`）で独立期待値と照合する。ここではGUI固有の操作・表示・終了と、同じ経路を代表する1形式の端から端までを確かめる。製品はテキスト入力を持たないため、GUIスレッドではIMEを無効にし、不要な入力方式の初期化が応答の判定に入らないようにする。

```powershell
.\out\x64\Release\wavplay_tests.exe --suite player_window
```

上のコマンドはGUI群の切り分け用。独立プロセスでの多重起動は `single_instance` 群、コンソールの試聴シナリオは `diagnostics` 群も実行する。

#### 起動と入力操作

**`--wav` のUnicode・空白、未知・重複・不足、廃止した `--driver`**

指定した1曲を保持し、曖昧な指定や起動引数での機器変更を拒否する。使用CLSIDはINIから取得する。

**CRTの起動引数分解**

試験実行ファイルの子プロセスへ生のコマンドラインを渡す。CRTのwide argv（製品の `__wargv` と同じ分解）と `parse_player_options` で、空白・タブ・部分引用・UNC・末尾の円記号・`\"`・引用内の `""` を含む--wavパスを期待どおりに得る。空の引用・余分な引数・値なしは引数エラーにする。

**多重起動と前面化**

- 入力・操作　同一ユーザー・セッション内で独立プロセスを同時起動し、GUI準備待ち、最小化、終了競合、異常終了、未準備/ハングを試す。
- 合格条件　主所有者は1つだけで、後発は追加の設定読込・機器初期化を行わない。準備完了後に既存GUIへ復元/前面化を依頼し、OSの制限時はタスクバー通知。所有者終了後は引き継げ、応答不能でも期限内に終了し二重起動しない。

**未設定・欠落機器、Nameと出力ペア、設定エラー**

NO DEVICEと設定案内、または初期化・設定のエラーを表示してPlayを無効にする。名前とペアを読み取り専用表示し、機器の一覧・選択・変更コントロールを持たない。

**init/start/stop/dispose/Releaseをゲートで待たせる**

別スレッドからのウィンドウメッセージに500 ms以内で応答する。未完了のPlaying/Stopped/Closedを表示しない。

**ボタン、Space、Escape、キー長押し、80回の連打**

確定状態と表示が一致する。保留Play/Pauseと重複Stopが積み上がらず、余分な再生が始まらない。Stopボタンがキーの宛先でもSpaceはPlay/Pauseになる。

**起動直後、ボタン無効化、再アクティブ化時の実フォーカス**

- UIスレッドのGetFocusがメインウィンドウか有効な子コントロールを指す。その配送先へのSpace/Escapeで操作でき、ファイル欄の選択を要しない。初期化後（再アクティブ化を含む）はリスト。再アクティブ化の前にフォーカスしていたStop・リストは、再アクティブ化の後も同じ。フォーカス中のStopをEscapeで無効にするとリストへ移り、Error欄へ移らない。そのリストでEnterを押すと選択曲を再生する。
- 再生中にフォーカス中のStopからCloseすると（`Release` を止めてClosingの間に見る）、リストも無効になり、フォーカスは枠に残って読み取り専用の欄へ移らない。

**Tab/Shift+Tab、Enter、Alt+P/Alt+S、修飾付きSpace/Escape**

読み取り専用のFile/Error欄を含めて標準のフォーカス移動ができる。Enterはフォーカス中のボタン、アクセスキーは対応ボタンを操作する。Ctrl/Shift/Alt付きSpace/Escapeを再生操作に転用しない。

**WM_COMMANDの送信元**

IDだけを一致させた偽の通知を受け付けず、対応する子ボタンのBN_CLICKEDだけで操作する。

#### GUIからの再生と拒否

**Pause/Resume、Stop後のPlay、EOF後のPlay**

Pauseを保持し、StopとEOF後の再生は先頭PCMから始まる。

**代表形式のサンプル一致と操作**

- 48 kHz・3バイト格納のステレオPCM24を、既定の開始無音100 msで実際のGUIから24 bit LSBの模擬ASIOへ流す。正負の端値・下位8 bitの値を含む4,099フレームを使い、8 KiBの読み取り境界と末尾の部分ブロックをまたぐ。Pause前後を連結して全有効フレームを独立期待値と照合する。Stop前は元WAVの先頭部分、再生中/一時停止中のStop後と自然終端後のPlayは先頭から全曲と一致し、欠落・重複がない。
- 再生中・一時停止中のCloseはいずれもバッファー・WAV・ドライバー参照を解放し、元レートを復元する。

**精度不足の出力**

全無音のPCM24を、32 bit容器内の有効20 bit（Int32LSB20）の左右へ出す。値が収まる音源でも拒否してGUIに理由を表示し、Playを無効にする。バッファー作成・start前に止め、Closeで終了コード1を返してドライバー参照とWAVを解放する。出力型ごと・片側だけの拒否は `output_format` で確かめる。

**ASIOを開く前の入力拒否**

2秒のリングを超えた最終サンプルの未使用ビットが非ゼロのステレオExtensible 24/32を開く。ドライバーを開かずにGUIに理由を表示し、Playを受け付けない。バッファーを作らず、Closeで終了コード1を返してWAVを解放する。形式ごとの拒否条件は `wav_header`・`wav_reader` で確かめる。

#### 応答・解放・セッション終了

**初期化中・再生中・停止中・Release中のClose**

UIを処理し続け、解放完了までHWNDを保持し、すべてのバッファーと機器参照を解放する。

**init/start失敗、終了時のレート復元失敗**

理由を表示し、再Playを拒否する。終了時の新たな失敗は解放後に表示し、再Closeで終了できる。

**外部WM_QUIT、作成失敗、ウィンドウの早期破棄**

非同期の解放完了を待ち、正常時は指定終了コード42を保持する。故障時は確認待ちせず1を返す。作成失敗でWM_QUITを残さず、次の作成が成功する。

**通知が待つ間の外部からのDestroyWindow**

- 入力・操作　表示中に再生し、UIスレッドを試験のフックで止めたまま次の整数秒まで送る。製品が通知を投稿したら、そのフックがUIスレッドからウィンドウを破棄する（キューの通知は捨てられ、合流の印が立ったまま残る）。その後のClosingの間は `Release` を止める。
- 合格条件　破棄までの通知の投稿を5秒以内に見る。WM_NCDESTROYが投稿先を外すので、その後のclosing・closedはイベントでUIを起こし、終了コード0で終わる。streamを1回止め、全参照・バッファーを解放する。投稿先を残す変異では終了の期限で不合格になり、試験の後始末はウィンドウがなければUIスレッドへWM_QUITを送るので群は止まらない。

**セッション終了（`WM_QUERYENDSESSION`・`WM_ENDSESSION`）**

| 入力・操作 | 戻り値と解放の判定 |
|---|---|
| 再生中にログオフの問合せ、続いて `wParam=FALSE` の取消し | 問合せはTRUE、取消しは0。再生を続ける |
| 再生中にTRUEで終了。通常のメッセージループ、入れ子のループ、元レートへの復元を拒否する機器 | 3.5秒未満（製品上限4秒の前）に0を返す。正常時はこの時点でstream停止、バッファー解放、元レートでのドライバー解放、外枠矩形の保存が済み、確認なしに終了コード0。入れ子の場合はそのループ内でウィンドウを破棄する。復元拒否では終了コード1 |
| Closed表示で終了処理エラーの確認待ち中にTRUE | クリックを待たず、終了コード1 |
| 停止中のCloseで `Release` を保留。Closingの描画と通知処理が済んだら入れ子のループに入り、別スレッドからTRUEを送る。ウィンドウの理由が有効な待機中に解放を進める | 0を返し、待機後の通知で入れ子のループ内でウィンドウを破棄する。終了コード0 |
| 停止中に `Release` を保留し、別スレッドからのTRUEが戻った後に解放を進める | 送信から4秒以上、4秒＋`hang_budget(2s)`（Releaseで計6秒）未満で、解放を待たず0を返す。ウィンドウの理由を外してClosingを表示し、解放を進めると終了コード0、残存参照なし |

**UIスレッドの実行速度方針**

- 入力・操作　制御STAの `init` を止めている間、止めを解いた後、Closeで `run_player_window` から戻った直後に照会する。
- 合格条件

  - ウィンドウがある間、UIスレッドは `ui::ui_thread_speed`（現在はWindows既定）の指定、戻った直後も既定。制御STAは `WAV Player control` の名前で既定のまま、STAから起動したスレッドも既定。UIスレッドの優先度・メモリー優先度は呼出し前から復帰後まで保持し、制御STAは未変更の参照スレッドと同じ継承値を保つ。プロセスのメモリー優先度をLOWにした場合も確認する。
  - プロセスの優先度クラスと電源調整は、群の最初のウィンドウの前と比べて、作成の前・ウィンドウがある間・終了後とも変わらない。どのスレッドでも、未対応以外の照会の失敗は不合格とする（未対応のWindowsでは注記して判定しない）

#### 進捗表示とウィンドウ設定

**出力ペアとバッファー診断の表示**

- 入力・操作　長いUnicode機器名、1/2以外のペア、最小ウィンドウとDPI変更、大きい能力値を使う。無効手動幅・create拒否・照会失敗・矛盾rangeと、Stop/再Play・Pause/Resume・再初期化を試す。
- 合格条件　Outputが機器名に隠れず、Bufferの全情報を折返し・スクロール・コピーで確認できる。要求、現在/最後の検証済み確保、照会時レートと能力を区別する。幅/確保拒否では確認済み能力だけを残し、照会自体が失敗なら能力も作らない。次のPlay/再初期化で古い能力と確保を消す。新しいレートの照会結果を使い、未確保の幅からmsを作らず、追加の能力照会や代替幅での再試行を行わない。

**表示文字列の整数整形**

対応8レート×1～8192フレームのmsを`std::format(L"{:.3f}")` と一致させ、48 kHzの丁度半分（3/9/15/33フレーム）は偶数へ丸める。負の粒度・LONG端値・64 bit最大値、m:ss/h:mm:ssの境界も期待値と一致する。正の整数でないレートはms・Hzを丸めず省く。ms整形を直接レート0で呼んでも除算せず、何も追記しない。

**最小化中の再生の進捗**

- 入力・操作　再生中に最小化し、次の整数秒までコールバックを送って制御側を起こす。製品がウィンドウへ投稿したWM_APPの範囲のメッセージを、UIスレッドのフックで数える。時間欄を読むたびにUIが起き、保ったrevisionで描くので、その秒が見えるまで読み、入力の区切りで投稿を取り出させてから数える（スナップショットはリスナーと同じロックの後なので、投稿があれば区切りより前にある。固定の待ち時間は使わない）
- 合格条件　最小化中の進捗は投稿しない。SC_RESTOREの後も新しい投稿なしで時間欄がその秒を示す。復帰後の次の秒は投稿して表示する。再び最小化した後のPauseは投稿し、Closeでウィンドウが終わる。復帰だけが最小化中の進捗を描くこと（強制更新の印）は、読み取りが描くので確かめない。

**進捗の描画の文字列キャッシュ**

- 入力・操作　非表示のウィンドウで再生し、次の整数秒まで送る。UIスレッドのフックで子コントロールごとのWM_SETTEXTとWM_ENABLEを数え、その秒が見えた後の入力の区切りで差を取る。
- 合格条件　その秒の描画は時間欄へWM_SETTEXTを1回だけ送り、ほかの14の子コントロールへは送らず、有効・無効も変えない。リテラルの文字列も変化のある時だけ設定する。

**UI故障後の無関係な起床**

- 入力・操作

  - 非表示のウィンドウを停止中にし、保留操作の欄へWM_CLOSEを送る（DefWindowProcがUIスレッドで破棄する）。外枠を広げると `WM_SIZE` の配置がその欄を置けず、UI故障になる（製品の試験用フックは使わない）。故障がCloseを要求するので、Closedと有効なCloseを待つ。
  - UIスレッドのフックで子コントロールごとのWM_SETTEXTとWM_ENABLEを数え、投稿したWM_MOUSEMOVEと送信したWM_NULLで16回起こす。前後とも入力の区切りの後に送信を2回往復させ（2回目は1回目の後の `refresh()` が戻ってから処理される）、その間の差を取る。

- 合格条件　Error欄に `DeferWindowPos` の故障を示し、Closed・`&Close`（有効）を表示してPlay・一覧を無効にする。その後の起床ではどの子コントロールにもWM_SETTEXTを送らず、有効・無効も変えない（故障後の描画も公開revisionごとに1回）。Closeで終了コード1を返し、ドライバー参照・バッファーを解放する。

**例外の文の復号**

- 入力・操作　`ui::exception_message` へ、継続バイトで始まるUTF-8でないバイト列 `93 FA 96 7B` の `runtime_error`。
- 合格条件　試験が独立に `MultiByteToWideChar(CP_ACP)` で復号した文と一致し、復号できない場合の固定文にならない。

**UnicodeとWindowsのシステムエラー**

UTF-8の日本語を保持し、Win32エラーはFormatMessageWによる文字列と操作名を表示する。

**96/144/192 DPIの通知、設定変更、最小寸法、繰り返し開閉**

システムフォントを変更し、全コントロールがクライアント内に収まる。DPI通知と実DPIでの設定変更を区別して照合する。ウォームアップ後の反復でGDI/USER資源数が増加しない。

**移動・サイズ変更後の終了と再起動、最大化・最小化、画面外や極端な保存矩形**

通常時の外枠の物理スクリーン座標と最大化状態を保存・復元し、最小化でも通常矩形を失わない。現在の作業領域と最小寸法に補正し、操作できる位置へ表示する。

**終了時の設定保存失敗**

ドライバー解放後に理由を表示し、UIの応答を保って再Closeで終了コード1を返す。既存設定ファイルを破損せず、保存失敗を正常終了として扱わない。

## Windows とオーディオ機器で確認する項目

### リリース全体の確認

試験者はWindows 11 25H2以降のx64で、単一起動・前面化、キーボード、リサイズ、時間とバッファーの表示、設定復元を操作し、OSビルドを記録する。初回公開候補と音声経路の変更時には、次の手順で実際のx64 ASIOドライバーと物理出力を確認する。別のドライバーは個別に判定する。

機器が拒否したレートでは、機器の非対応とアプリの拒否動作をそれぞれ記録する。発生させられない通知は実機欄を「未実施」とし、模擬ASIOの結果を別に残す。聴感、物理出力の測定、模擬ASIOの全バイト照合には、それぞれ観測した結果を記す。表示や出音だけから物理出力の全サンプル一致や一般的な音質改善は判定できない。

## 実機試験の手順

### 準備

1. 自動検証を通したReleaseを使い、他のプレーヤーを終了する。再生機器の音量を下げ、利用するx64 ASIOドライバーを指定する。
2. `scripts/check-asio-drivers.ps1 -Json` で登録を確認し、対象のCLSIDを手元の設定へ記入する。このコマンドはドライバーをロードしない。
3. 試験前のレート、バッファー、接続、出力ペアを控える。製品が変更するサンプルレートと、ドライバーが保持する推奨幅を別の値として扱う。
4. 対象コミット、EXEのSHA-256、OSビルド、ドライバーの版、入力形式・レート・長さ、操作、結果を記録する。機材識別情報・個人パス・音源名を含む実行記録は `private/results/` に置き、公開文書へ転記しない。

```powershell
$driverClsid = Read-Host 'ASIO driver CLSID'
.\out\x64\Release\wavplay_tests.exe --probe-asio $driverClsid
```

照会を2回行い、現在レート、出力型、バッファー範囲・粒度の取得と解放・再オープンを確認する。失敗した場合は操作とエラーを記録する。音声を出す診断は、再生の準備を整えてから別に実行する。

### 試験音源と操作の記録

試験者がWAVを用意し、形式・レート・長さ・期待する左右の信号を控える。機器で使用できる出力型と精度を使う。自動試験が生成するWAVは模擬出力照合用で、実機用音源として配布しない。

- GUIの操作には短い48 kHz・PCM16を使う。PCM24には、下位8 bitにも値があり、滑らかな立ち上がり・立ち下がりと末尾無音を含む48 kHzステレオの音源を使う。どちらもPlay/PauseとSpace、StopとEscape、連打、自然終端、再生中・一時停止中のCloseを同じGUIで試し、応答・表示・終了後の再オープンと聴感を記録する。
- コントローラー試聴用の6秒WAVは、各トーンに20 msの立ち上がり・立ち下がりを焼き込み、末尾0.5秒を完全な無音にする。プレーヤーはWAVをそのまま出力し、再生時にフェードを加えない。自然終端に異音が出たときは操作途中のクリックと区別し、記録して調査する。

### 操作と合否

#### 起動・物理出力

**機器未設定と設定後の起動**

未設定ではNO DEVICEと案内を表示しPlayを無効にする。有効な機器設定で再起動すると指定機器・出力ペアで停止状態になる。不正値や登録欠落では代替機器を開かない。

**左右とモノ**

左右を識別できる低レベルのステレオ音源とモノ音源で、指定した出力ペアとモノの両側出力を確認する。複数ペアを使える機器はOutputPairを変更して再起動する。

**レート**

製品が対応する44.1／48／88.2／96／176.4／192／352.8／384 kHzについて機器の受理・拒否を確認する。受理したレートでは各10秒以上再生し、表示と出音を確認する。機器非対応と、対応を報告した後の切替失敗・表示不一致・無音を区別する。

**BufferSize**

0／未設定はそのレートの現在の推奨幅、対応する正値は指定幅になる。不正値や範囲外では代替幅を使わず拒否する。実幅・範囲・粒度・ブロック時間を画面と照合する。終了後も推奨幅を保持するドライバーでは、次回の0／未設定がその推奨幅を使うことを確認する。

**StartSilence**

未設定の100 msと0～1000 msの指定、ブロック単位の切上げ、不正値の拒否を確認する。再生開始・再開・異レート曲間の先頭に適用し、同一レート曲間には追加しない。

#### 再生・曲間・終了

**Pause／Resume・Stop／Play**

Pauseからは未再生位置を、Stop後のPlayは選択曲の先頭を確認し、左右も照合する。停止・再開時の音声と無音の不連続で生じたクリックは、その操作と位置を記録する。Stopで残りを打ち切ることと、再開・再Playでの欠け・飛び・重複、再生中の歪み、実装に起因する異音は区別する。後者は不合格。

**曲間**

同一レートで連続する波形を分割した曲間は、クリックも途切れもないこと。異レートでは切替後の表示と出音を確認する。機器が次曲を受理しなければ、その項目で停止する。

**reset・幅変更通知**

発生させられる通知で、停止・同じ機器の再初期化・位置0での停止待機を確認する。自動再生せず、起動時の設定を保持する。

**Close・再オープン**

製品が変更したレートを元に戻し、停止・解放後にドライバーを再度開けることを確認する。終了直後の推奨幅は別に記録し、終了前との一致は合格条件にしない。別診断で幅を戻した場合は、その操作後の照会を区別する。[推奨幅の方針](asio-contract.md#推奨バッファー幅の保持と終了時の方針)

#### 設定保存・長時間再生

**ウィンドウと設定保存**

移動・リサイズ・最大化・最小化後の終了と再起動、モニター構成変更での位置補正を確認する。起動後のINI手編集・コメントを保持し、保存失敗では既存設定を壊さずエラーを表示する。

**長時間再生**

受理した最高レートと安定して使える最小幅で30分再生し、表示中と最小化のそれぞれで途切れ・異常停止・ハングを確認する。

## 公開候補とローカル再生用フォルダーの確認

### 公開ソースとビルドPC

公開候補を確認する担当者は、ソースを `build/public-files.txt` に照合し、公開用履歴の内容も確認する。SDK・実行物・個人設定・実験記録・音源・秘密情報、および `private/`・`out/`・過去の開発履歴を公開用履歴へ持ち込まない。実行記録は公開用文書には含めない。

1. `scripts/check-public-source.ps1 -Tracked` で追跡ファイルを確認する。構成・文書を変えた場合は `scripts/check-project-layout.ps1` でVisual Studio登録とリンクを確認する。
2. SDKのないビルドPCで `build.cmd -FetchSdk`、配置済みのPCで `build.cmd` を実行する。前者は公式ZIPのハッシュ、両方でReleaseの生成を確認する。SDKの版違い・取得失敗・ハッシュ不一致は失敗とする。
3. 新しい `-OutputDirectory` に作成でき、既存の出力先を上書きしないことを確認する。ビルド中に機器を開かず、再生しない。

### 移動先の再生環境

担当者は `out/player/` を別の書き込み可能な場所へコピーし、Visual StudioとSDKのないWindowsで以下を確認する。

1. 日本語と空白を含む配置先で、別の作業ディレクトリから引数なしの `setup.cmd` を実行する。Windows標準の `powershell.exe` を通り、スクリプト隣にUTF-8の設定・一覧を作成し、期待した曲順で停止起動することをファイルと画面で確認する。元ソースの配置やビルドPCの絶対パスに依存しない。
2. 設定済みフォルダーでの再実行、入力の取消し、ドライバー未登録、空の音源フォルダー、書き込み失敗を試す。既存の設定と音源を黙って上書きせず、失敗時には再生を開始しない。
3. PowerShellの引数をすべて明示する試験では、CMDの引数なし起動と既定パスを確認できない。通常起動の合否は終了コード、作成したファイル、GUIの停止表示を合わせて判定する。

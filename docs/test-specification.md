# WAV Player の試験計画

この文書は現行の受け入れ条件と検証手順をまとめる。実行結果は試験対象と条件を添えて別に記録し、この仕様から過去の試験完了を推定しない。

ソリューションのビルドと SDK ヘッダーの検査で確認できるのは開発環境まで。再生機能は、実装した段階ごとに下表の入力を製品と同じコードに通して判定する。コマンドと現在実行できる検証は [README](../README.md) にまとめる。

## ドライバーなしで判定する項目

現在の PCM16/24/32 再生について、SDK の規定、任意機能の選択、仕様が定めない失敗時のホスト方針とそれぞれの試験を [ASIO 契約の照合表](asio-contract.md) に記す。

`wavplay_tests.exe` は失敗したケースと期待値・実測値・判定の位置（ファイル:行）を表示し、1 件でも失敗なら非ゼロで終了する。引数なしでは試験群ごとに子プロセスで実行し（既定で最大4群を並行）、PASS・FAIL・TIMEOUT・CRASH を区別して集計する。`run_timed` と再生用の補助の監視による停止、`std::terminate`・`abort`・CRT の不正パラメーターと Debug の CRT 報告、AddressSanitizer が扱わない未処理の例外は、現在の群とケースを表示してから終了する。ケースの監視がない箇所の停止は群ごとの上限で強制終了し、fail-fast（0xC0000409）や AddressSanitizer の報告（86）とともに群だけを表示する。どの場合も後続の群は続けて実行する。待機の上限は Release を基準に Debug で3倍、ASan で4倍とし、製品の時間は変えない。ドライバー固有の呼び出しだけをプロジェクト所有の模擬 ASIO に置き換え、製品と同じ `asio::DriverSession` での開始・停止・コールバック経路を試す。期待バイト列は製品の変換関数で生成しない。

| 対象 | 試す入力・操作 | 合格条件 |
|---|---|---|
| WAV/RF64 | 対応形式・レート・チャンネル、チャンク順の入れ替え、未知の奇数長チャンク。RF64 は小さなヘッダーと疎ファイル等で 4 GiB をまたぐシーク・読み込みを試す | データ開始位置とフレーム数が一致し、境界前後から既知のサンプルを読み出せる |
| 拒否する入力 | ヘッダー・データの切断、必須チャンクの欠落・重複、サイズ加算のオーバーフロー、フレーム端数、不正な形式・有効ビット数、24/32 の末尾付近の非ゼロ未使用ビット | 再生開始前に拒否し、不正領域を読まない。開いた後の I/O 故障では停止する |
| WAV の再開カーソル | 検証後にヘッダー領域を読み取りロックして独立カーソルを開く。そのカーソルだけで PCM の読み取り失敗も起こす。検証済みで未読の reader を再生要求へ移譲する | 再開時にヘッダーを再読せず、元と同じ形式・データ位置で読む。失敗したカーソルは閉じ、元カーソルの位置と読み取りを保つ。要求の寿命中はファイルの書き換えを拒否し、終了後はハンドルを解放する |
| 形式判定・変換 | 入力と ASIO サンプル型の全組み合わせを要件の許可表と照合する。各対応変換で正負の端値、左右で異なる値、モノ、LSB/MSB、32 bit 容器内配置を試す。Float は符号付きゼロ、subnormal、無限大、NaN も含める | 許可した出力だけが独立した期待バイト列と一致する。データがたまたま収まる入力でも形式として精度が不足すれば開始を拒否する |
| リング・曲間 | 連番フレームをリング一周以上流す。長さがブロック幅の 1 手前・同じ・1 超、ブロック幅に満たない複数曲、同一レート曲間、レート変更、次曲非対応を試す | 先頭の事前充填を含め、最後の有効フレームまで左右の連番が各一度だけ届く。互換曲間にゼロが挟まらない。レート変更は旧曲を排出してから行い、非対応曲ではその項目で停止する |
| アンダーラン・終端 | 読み込みを遅らせてリングを空にする試験と、正規の EOF を含む短い曲を最後まで出す試験を分ける。停止処理までの追加コールバックも発生させる | 前者は直ちに停止を要求し、無音による再生継続や古い音の再利用がない。後者は末尾の有効サンプルを欠かさず正常停止する。数えた排出の後も2ブロック分の実時間は無音を返してから stop する。STA にメッセージが連続しても単調時計の期限を守り、その間のドロップアウトは `underrun` とする |
| 機器とバッファー | 設定CLSID/出力ペアの欠落、1/2以外のペア、レート拒否、推奨/有効/無効サイズ、初期化・バッファー作成・開始での失敗、開始失敗後の再試行 | 模擬 ASIO の呼び出し順、設定値、ダブルバッファーが一致する。BufferSize=0／未設定はバッファー作成時の実レートで照会した推奨幅を選び、起動時の推奨値へ固定しない。正値は現在の範囲・粒度で検証してそのまま使用する。設定した左右のチャンネルだけを照会・作成・作成後検証し、別の機器・ペア・サイズへの代替や解放漏れがない |
| 停止中の能力照会 | 指定 CLSID を開き、現在のレート、出力数、出力1/2で異なる型、バッファー幅の4値を照合する。初期化と各照会にも個別に失敗を返す | レート設定・バッファー作成・再生開始を呼ばない。成功時と失敗時の両方で取得済みの参照を解放し、同じ CLSID を再度開ける |
| バッファー作成時の診断 | 模擬機器の作成時の幅を512、破棄後の推奨幅を544フレームとし、出力遅延には1ブロック未満の値を返す。後続区間の出力検証・開始も個別に失敗させる | 各区間の開始前に作成指定幅・実レート・左右の型・報告された出力遅延がそろう。停止後の照会や後続区間の失敗が、検証済みの記録を上書きしない |
| 出力ペア・バッファーの表示 | 長いUnicode機器名、1/2以外のペア、最小ウィンドウとDPI変更、大きい能力値を使う。無効手動幅・create拒否・照会失敗・矛盾rangeと、Stop/再Play・Pause/Resume・再初期化を試す | Outputが機器名に隠れず、Bufferの全情報を折返し・スクロール・コピーで確認できる。要求、現在/最後の検証済み確保、照会時レートと能力を区別する。幅/確保拒否では確認済み能力だけを残し、照会自体が失敗なら能力も作らない。次のPlay/再初期化で古い能力と確保を消す。新しいレートの照会結果を使い、未確保の幅からmsを作らず、追加の能力照会や代替幅での再試行を行わない |
| 異レート曲間の再初期化 | 所有セッションで48→44.1 kHz と44.1→48 kHz を連続再生する。模擬機器は、同じ初期化内でバッファーを一度作った後のレート変更では前のレートの幅を返し続ける。2回目の初期化を失敗させる | 曲間で旧区間を解放し、元レートへ戻してからドライバーを解放する。同じウィンドウで初期化し直し、overload の能力照会をやり直す。実レートが次曲と同じなら設定せず、新しい初期化が返す幅で作成する。初期化失敗では2曲目を開始せず、元レートのまま参照を解放する。44.1→48 kHz で旧インスタンスが元の48 kHzへの復元を通知した場合は続行する。復元中のクロック喪失や reset は2曲目の開始を止める。新しいインスタンスで設定を変えていなければ、最終解放時に外部のレート変更を上書きしない |
| 開始時の無音 | 所有セッションの既定値で、48 kHz の1曲、同一レートの2曲、48→44.1 kHz の2曲を再生する。範囲外の長さも指定する | 各区間の最初の9ブロック（B を含む）が無音で、その後は無音なしの再生と同じバイト列になる。同一レートの曲境界に無音が入らない。範囲外の指定ではドライバーを開かない |
| 単曲の一時停止・再開 | 48 kHz の連番入り WAV を開始時の無音中・曲途中・最後の部分ブロックの提出直前で一時停止する。位置取得は正常・全0・未対応、出力は16/24 bitで試す。繰り返し停止と、最終ブロック提出後の要求も試す | ASIO への提出列とは別に、出力遅延を持ち stop で残りを捨てる模擬 DAC キューを使う。停止前と再開後に実際に出た左右の有効フレームが、元 WAV と欠落・重複なく完全一致する。先読みが曲末まで済んでいても飛ばさない。開始無音中の保持位置は0。停止中は出力が進まず、再開時は新しいバッファーと開始無音を使う。EOF提出済みなら completed を優先する。位置APIへの依存はない |
| 一時停止・終端の排出境界 | start 内の切替なし・複数回の切替、出力遅延0・1ブロック未満・複数ブロック、1フレーム・事前充填Bの内外で終わる曲、start 内での一時停止要求 | 独立した模擬 DAC キューの出力を16/24 bitで照合し、最後まで欠落・重複がなく、stop による未再生 PCM の破棄がない |
| 単曲の Stop と先頭からの Play | 48 kHz・PCM16の連番入り WAV を開始無音中・途中・曲末直前・EOF提出済みの排出中にStopする。位置APIは正常・全0・未対応、出力は16/24 bit。一時停止中・曲末からのStop、繰返し、Pauseとの両順序の競合も試す | 独立した模擬 DAC の停止までの出力は元 WAV の先頭部分と一致する。Stopではキュー内の未再生PCMの破棄を許す。停止後の位置は0、次のPlayは先頭から全フレームが欠落・重複なく一致する。新しいバッファーと開始無音を使い、位置APIを呼ばない。追加callbackなしでも制御側がStopを受理する |
| Stop の故障・寿命境界 | start・stop・dispose中のStop、Stopとreset/buffer-size-change/overload/先読み失敗、停止・解放失敗、idle Stop前後の通知を試す。試聴CLIの通常Stopとpaused→Stopを同じ所有セッションで実行する | StopはPause・EOFより、再初期化要求はStopより、故障は再初期化要求より優先する。Stopで通知の結果を消さない。未報告の停止中通知は、同期APIの次のPlayがドライバー・バッファー・位置に触れずに結果を返す。reset/buffer-size-changeはreinitialize_required、他は故障固有の結果とし、回復処理なしの次のPlayは拒否する。通常Stop成功時はASIOバッファーと生産者を解放し、選択WAV・初期化済みドライバーを保持する。再生中の同期stopは例外。CLIの再PlayはWAV先頭から全バイト一致し、初期化は1回。早期EOF・例外で長いタイマーをキャンセルし、待機中のreset/WM_QUITで再Playせず解放する |
| 非同期の単曲制御 | 48 kHz PCM16の1曲でPlay/Pause/Stop/Closeを別スレッドから送る。重複Play、Pause→Play、Stop→Playの即時連続、排出中Pause→Stop、曲末後Playを試す。再開後の再生中に重複Playを送り、ほかの要求なしで曲末まで再生する | Playはstart成功後、Pause/Stopは解放後に完了番号を進める。番号は後退せず受付を超えない。再生中の重複Playはすぐ確定し、その後の曲末でも番号はその重複Playから戻らない。16/24 bitの出力を独立期待値と照合し、Pause前後は全曲と、Stop後や曲末後のPlayは先頭から全曲と一致する。キューを処理するために再生を再入しない |
| 制御の非同期受付と終了 | 模擬initとstopを明示的なゲートで止め、その間に受付・状態照会・後続Playを行う。32件満杯でCloseを送る。停止中・再生中・一時停止中・初期化失敗・start失敗・dispose失敗・元レート復元失敗でもCloseする | 受付がI/Oや解放を待たず、受付番号と完了番号を区別できる。Closeは満杯でも受理され、以降の操作を拒否して保留Playを開始しない。全ドライバー操作とReleaseは所有ウィンドウと同じSTA上で行い、Release後にウィンドウを破棄する。48 kHzへの変更を元の44.1 kHzへ戻す。失敗もclosed後まで記録し、参照・バッファーを解放する |
| コントローラー試聴CLI | 6秒の48 kHz PCM16 WAVを使い、pause-resume、stop-play、select-play、close-playing、close-pausedを模擬ASIO24 bit出力で実行する。入力不適合とClose中のoverloadも試す | 不適合音源はactivation前に拒否する。各操作の受付と完了を待ち、前3件は全フレームの終端位置、後2件は意図した終了を確認する。select-playは1秒以上進んだ同じ項目を再生中に再選択し、位置0・曲番号・レート・長さを照合する。Close中の例外なしfaultも成功扱いせず、全経路で元レート復元・解放・joinする。CLIは位置と操作手順の確認であり、PCM一致は独立した模擬出力の全フレーム照合で確認する |
| 制御とWindowsメッセージの公平性 | initをゲートで止めて32件のPauseと同じSTAのメッセージを準備する。別に、イベントとメッセージの両方が待機前から届いた状態で1回だけwaitする。callback停止中はPlayを連打する | 最初の要求バッチより前に既着メッセージを処理する。イベント優先でwaitが返る場合もメッセージを処理済みにする。各バッチを有限件数に制限し、メッセージのdispatch中にキューロックを持たない。操作通知が続いてもcallback監視期限を延ばさない |
| 制御の起動・解放境界 | create/start中にPause・Stop・Closeを、stop/dispose中に次のPlayとCloseを送る。停止・一時停止・EOF後にreset/buffer-size-change/overloadを通知し、Playの開始状態の公開時（アイドル監視の後）にも通知する。WM_CLOSE/WM_QUITでも終了する。コンストラクター失敗・同時作成拒否・暗黙Closeも試す | 未開始のStop/Closeはstartを避け、解放中のCloseは保留Playを取り消す。reset/buffer-size-changeは再初期化して停止待機し、overload等の故障はPlayを拒否してClose後まで残す。アイドル監視より先にPlayへ届いた通知も開始せず同じ方針で処理し、汎用の拒否例外へ置き換えない。追加callbackなしでWin32終了が完了する。所有権を二重取得せず、構築失敗・デストラクター後に新しいコントローラーを作れる |
| 通知後の再初期化と停止待機 | 再生中、stop/dispose中、Stop・Pause・EOF後にreset/buffer-size-changeを送る。再initで幅・出力型を変え、起動後のINI編集、保留Play、再初期化中の操作も試す | 旧バッファー・リング・生産者を解放して元レート復元とReleaseを済ませ、同じCLSID・STA・所有ウィンドウ・起動時設定で再initする。overloadの能力とクロックを再照会する。再初期化中はCloseだけを受理し、保留操作の完了番号を取消しとして確定する。WAVの保護ハンドルと検証済みメタデータを保持し、位置0のstoppedで待つ。start・createBuffers・先読みを自動で行わず、INIを読み直さない。回復後の新しいPlayだけが出力型・幅を再照会し、先頭から全フレーム一致する。手動幅の不適合は代替なしで拒否する |
| 再初期化の失敗・競合 | 元レート復元、再activation/init、能力・クロック照会を個別に失敗させる。回復要求とoverload/クロック喪失/stop・dispose失敗を両順序で競合させ、再init中のreset/buffer-size-change、遅延した旧世代の通知、各境界のCloseも試す | 故障は再初期化要求より優先し、取得済み資源を解放してfailedを残す。再init中の新たな要求も自動再試行を繰り返さない。古い世代の通知は新しい要求へ波及せず、新しい世代の通知は消さない。Closeは呼び出し境界で再初期化を中止し、保留Play・次のstartを実行しない。参照・WAV・所有ウィンドウ・STAを順に解放する |
| 最終Releaseの通知 | Stop・Pause・EOF後のCloseで48→元の44.1 kHzへ戻し、Release中に正常な復元レート・reset・buffer-size-change・overload・0 Hzの通知を個別に送る。通知段階の切替前の通知と遅延した旧段階・旧要求の通知も試す | 正常な復元通知だけは元の停止結果を保ち、reset/buffer-size-changeはreinitialize_required、overload/クロック喪失は故障としてclosed後も残す。Close中は再初期化しない。切替で既着通知を消さず、旧段階のクロック通知と同じ要求内の通知を区別する。元レートの実値も一致し、全参照を解放する |
| 一時停止中の故障・再初期化要求 | 排出・stop・dispose 中の overload/reset/buffer-size-change、開始・停止失敗、pause と先読み失敗の競合、一時停止後の待機中の reset・buffer-size-change・overload・クロック喪失 | paused として位置を確定せず通知の結果を返し、回復前の同じ要求の再開を拒否する。同期APIで待機中の通知を受けた次のPlayは、保持位置から再開せず結果（reset/buffer-size-changeはreinitialize_required、overloadはunderrun、クロック喪失はdriver_error）を返し、確定位置を保つ。コントローラーの再初期化成功後は位置0で停止する。コールバックは先読み失敗を非消費で検出し、制御側も生産者の終了後に再確認する |
| Stop の準備・生産者の境界 | レート照会・create・latency検証中にStopを同期注入する。reset/buffer-size-change/overloadも両順序で競合させる。2秒リングを超える曲を開始無音中にStopする | setup中のStopではstart/stopせず、割当済みのバッファーだけを未書込みで解放する。再初期化要求はStopより、故障は再初期化要求より優先する。待機中の生産者も停止・joinし、通常Stop後の次Playでは先頭から全フレーム一致する |

曲間の試験には、短い曲の直後に、未使用ビットの検査に時間のかかる 24/32 音源を置く。有効なら境界に空白がなく、後続曲が壊れていれば手前の曲の末尾まで出力して停止する。

停止・再開の境界にクリックがあり得ても、有効フレームの期待値は元 WAV のままとする。フェード等による値の変更や、欠落・重複を許容して比較を緩めない。一時停止は前後を連結して元 WAV 全体と照合する。ユーザーの Stop は打ち切りまでの先頭部分と、次の Play の全曲をそれぞれ照合する。停止前後の無音は既存の開始・排出手順に従って区別する。

コールバックから到達する関数（`playback/segment_renderer.cpp`、`stream::PrefetchRing::Consumer` の `pop`・`read_failed` と `PrefetchRing::pop_block`、`PlaybackSignal` のインライン操作、`core/block_copy.h` のインラインのコピー・ゼロ埋め。[設計](architecture.md#スレッドとリアルタイム境界)）を実装変更時に読み、確保・待機・ディスク I/O・ログ・GUI 呼び出しを持ち込んでいないことを確かめる。Releaseでは `verify.ps1` が生成したReleaseの `wavplay.exe` の機械語をコールバックの入口から推移的にたどり、`SetEvent` 以外の取り込み関数、間接呼び出し、CRTの `memcpy`・`memset` を含む製品外の呼び出し先、スタックプローブ・GSクッキー・例外・確保の補助、浮動小数点演算（VEX形式も含む）、AVX512/EVEX、起動時の必須命令セットを超える命令、CRTのCPU再判定による分岐を拒否する。整数AVX2/BMIは[起動契約](architecture.md#命令セットの前提)の範囲で許す。起動ガードと製品側のCRT/TLS初期化・拒否後の終了処理は `scripts/verification/startup-code.ps1` で別にSSE4.2範囲へ制限する（[追加回帰](#品質改善の追加回帰)の「Releaseのコールバック経路の機械語」）。スピン待ちや意味の変化は機械語の監査では分からないため、読む確認は省かない。Releaseは起動ガードの2翻訳単位を除いて全体最適化（LTCG）でビルドするので、その対象の `.obj` は中間表現で機械語を持たない。生成コードの確認は出荷する実行ファイルの監査と逆アセンブル、またはリンク時に書かれる `/FAcs` の一覧で行い、翻訳単位ごとの `.obj` の逆アセンブルでは代えない（[最適化の方針](architecture.md#最適化の方針)）。ASan でメモリ境界を確認し、形式判定や左右の順序は出力バッファーの照合で確認する。

## 品質改善の追加回帰

共通PCM16照合器も検証対象とする。製品変換を使わない3フレームの独立した16/24 bit期待値を正例にし、ブロック不足、片チャンネル切断、サンプル改変、末尾無音や下位paddingの非ゼロ、余分なブロックを負例にする。Pause/Stopの途中結果を試すケースでは、必要な先頭・残部の範囲を呼び出し側で明示し、その範囲内を全バイト照合する。

電源要求の自動試験は資源寿命と要求種別の確認であり、実際の長時間スリープ抑止・画面消灯はWindows上の手動確認と区別する。先読み性能の時間値にはOSの揺らぎがあるため、同一PC・Release・予熱後の中央値と読み取り回数を記録し、時間だけで自動試験を不合格にしない。最適化・ツールセット・SDK・ソース配置などの条件が異なる生成コードや測定値を、同条件の比較として扱わない。

|---|---|
| 通常進捗のGUI更新 | 一覧の選択・スクロール照会を行わず、時間表示だけを更新する。状態通知と進捗通知が合流しても必要な状態更新を落とさない。同revisionでも復元時の強制更新は実行する |

## Windows とオーディオ機器で確認する項目

### GUIの接続

`--suite player_window` は製品と同じ `run_player_window` を独立UIスレッドで動かし、登録不要の模擬ASIOと実際のWin32コントロールを使う。GUIと制御層は入力・出力形式で分岐しないため、形式・出力型・チャンネル数ごとの変換と操作の一致は下位層の試験群（`wav_header`・`wav_reader`・`prefetch_ring`・`output_format`・`segment`、模擬DACを使う `track_player`・`track_source_formats`・`track_output_types`）で独立期待値と照合する。ここではGUI固有の操作・表示・終了と、同じ経路を代表する1形式の端から端までを確かめる。製品はテキスト入力を持たないため、GUIスレッドではIMEを無効にし、不要な入力方式の初期化が応答の判定に入らないようにする。

| 最小化中の再生の進捗 | 再生中に最小化し、次の整数秒までコールバックを送って制御側を起こす。製品がウィンドウへ投稿したWM_APPの範囲のメッセージを、UIスレッドのフックで数える。時間欄を読むたびにUIが起き、保ったrevisionで描くので、その秒が見えるまで読み、入力の区切りで投稿を取り出させてから数える（スナップショットはリスナーと同じロックの後なので、投稿があれば区切りより前にある。固定の待ち時間は使わない） | 最小化中の進捗は投稿しない。SC_RESTOREの後も新しい投稿なしで時間欄がその秒を示す。復帰後の次の秒は投稿して表示する。再び最小化した後のPauseは投稿し、Closeでウィンドウが終わる。復帰だけが最小化中の進捗を描くこと（強制更新の印）は、読み取りが描くので確かめない |
| 進捗の描画の文字列キャッシュ | 非表示のウィンドウで再生し、次の整数秒まで送る。UIスレッドのフックで子コントロールごとのWM_SETTEXTとWM_ENABLEを数え、その秒が見えた後の入力の区切りで差を取る | その秒の描画は時間欄へWM_SETTEXTを1回だけ送り、ほかの14の子コントロールへは送らず、有効・無効も変えない。リテラルの文字列も変化のある時だけ設定する |
| UI故障後の無関係な起床 | 非表示のウィンドウを停止中にし、保留操作の欄へWM_CLOSEを送る（DefWindowProcがUIスレッドで破棄する）。外枠を広げると `WM_SIZE` の配置がその欄を置けず、UI故障になる（製品の試験用フックは使わない）。故障がCloseを要求するので、Closedと有効なCloseを待つ。UIスレッドのフックで子コントロールごとのWM_SETTEXTとWM_ENABLEを数え、投稿したWM_MOUSEMOVEと送信したWM_NULLで16回起こす。前後とも入力の区切りの後に送信を2回往復させ（2回目は1回目の後の `refresh()` が戻ってから処理される）、その間の差を取る | Error欄に `DeferWindowPos` の故障を示し、Closed・`&Close`（有効）を表示してPlay・一覧を無効にする。その後の起床ではどの子コントロールにもWM_SETTEXTを送らず、有効・無効も変えない（故障後の描画も公開revisionごとに1回）。Closeで終了コード1を返し、ドライバー参照・バッファーを解放する |
| UIスレッドの実行速度方針（制御STAの `init` を止めている間、止めを解いた後、Closeで `run_player_window` から戻った直後） | ウィンドウがある間、UIスレッドは `ui::ui_thread_speed`（現在はWindows既定）の指定、戻った直後も既定。制御STAは `WAV Player control` の名前で既定のまま、STAから起動したスレッドも既定。UIスレッドの優先度・メモリー優先度は呼出し前から復帰後まで保持し、制御STAは未変更の参照スレッドと同じ継承値を保つ。プロセスのメモリー優先度をLOWにした場合も確認する。プロセスの優先度クラスと電源調整は、群の最初のウィンドウの前と比べて、作成の前・ウィンドウがある間・終了後とも変わらない。どのスレッドでも、未対応以外の照会の失敗は不合格とする（未対応のWindowsでは注記して判定しない） |

実機では自分で用意した48 kHz・PCM16の短い試験用WAVを同じGUIで使う。Play/PauseとSpace、StopとEscape、連打、自然終端、再生中・一時停止中のCloseを操作し、表示・応答・終了後の再オープンを確認する。聴感は試聴者の観測として記録し、画面から推定しない。[実機試験の手順](#実機試験の手順)

PCM24の実機確認には、自分で用意した48 kHz・ステレオの試験用WAVを使う。下位8 bitにも値を含み、音源側で滑らかな立上がり・立下がりと末尾の無音を持つものを選ぶ。上と同じ操作を行い、模擬ASIOの全サンプル一致と実機の動作・聴感を分けて記録する。

### リリース全体の確認

- Windows 11 25H2 以降の x64 で、単一起動・前面化、キーボード、リサイズ、時間とバッファー表示、設定復元を操作して確認する。実際に試した OS ビルドを記録する。
- 初回公開候補と音声経路の変更時は、利用するx64 ASIO機器でドライバーの初期化、各レートの可否、物理出力ペア、バッファー設定、停止・復帰、曲間、元レートの復元を確認する。終了後の推奨幅は独立に記録し、開始前との一致を正常終了の条件にしない。推奨幅を保持するドライバーでは、その後のBufferSize=0／未設定が現在の推奨値を使うことを確認し、正値指定と区別する。試験条件を揃えるために別診断で幅を戻した場合は、製品終了直後と別操作後の照会を分け、製品の自動復元とは扱わない。異なるドライバーでの互換性は別の確認として扱う。[実機試験の手順](#実機試験の手順)・[推奨幅の方針](asio-contract.md#推奨バッファー幅の保持と終了時の方針)
- ドライバーが拒否したレートは、アプリの拒否動作と機器の非対応をそれぞれ記録する。実機から任意に発生させられない通知は模擬 ASIO で再現する。音が出たことや DAC のレート表示から、全サンプルのビット一致を認定しない。
- 停止・再開時に音声と無音の不連続で生じるクリックは仕様として許容し、その有無だけで不合格にしない。発生した操作と位置を記録する。一時停止からの再開やStop後の先頭からの再生での欠け・飛び・重複、再生中の歪み、実装不具合による異音は許容しない。Stop自体による残りの打切りは意図した操作として区別する。同一レートで連続する波形の曲間にクリックや途切れがないという基準は維持する。聴感で確認した範囲と、物理出力を測定した範囲を分けて判定する。
- コントローラーの試聴では、音源側の各トーンに20 msの滑らかな立上がり・立下がりを焼き込み、末尾0.5秒を完全な無音にした6秒WAVを使う。自然終端で元音源の非ゼロ最終値を切る要因を除き、操作途中のクリックと区別する。プレーヤーはこのWAVをそのまま出力し、実行時のフェード処理は加えない。自然終端で異音があれば記録して調査し、単に境界だからという理由で合格にしない。

## 判定の順序

ローカル再生用フォルダーの `setup.cmd` は、Windows標準の `powershell.exe` を通る通常起動で確認する。別の作業ディレクトリ、日本語・空白を含む配置先で実行し、スクリプト隣のUTF-8設定・一覧、曲順、既存ファイルの保護、停止状態での起動を照合する。パラメーターをすべて明示したPowerShell単独試験だけでは、CMDの引数なし起動と既定パスを検証できない。終了コードだけで合格とせず、ファイル内容と画面を確認する。

ローカルと GitHub Actions では同一の検証入口（`verify.ps1 -Analyze -IncludeASan`）から、両プロジェクトの評価したビルド設定の監査、Debug/Release x64 の静的解析付き再ビルド、Release と Debug-ASan のコンソールテスト（Debug の実行時検査は Debug-ASan に含まれるため Debug では重ねない）、ビルド成果物の監査を行う。SDK検査と各機能の試験結果、ローカル再生用フォルダーの確認、実機確認を分ける。対象ソースと実行物のハッシュを検証結果に対応付け、未実行の項目は「未実施」、実行して条件を満たさなかった項目は「失敗」とする。ソース公開時のCIは `scripts/ci.ps1` から `check-public-source.ps1 -Tracked`、PowerShellの回帰試験、SDK取得、上記の全検証を実行する。

手動実行で `release_only` を選んだ場合だけ、`verify.ps1 -Configuration Release` によるRelease限定の診断を行う。診断モードは実行名とログに明示し、静的解析・Debug-ASanは未実施として扱う。診断の成功だけで全検証の合格とはしない。詳細ログはrunner内の一時領域に保持し、公開ログには合否、試験・ケース名、ソースのファイル名と行番号、数値の期待値と実測値を出す。既知の例外型は許可リストにある型名だけを再構成し、GUI送信失敗は固定の識別子・メッセージ番号・Win32エラー番号だけを表示する。例外の詳細やローカルパスは出さず、実行物をartifactやReleaseへアップロードしない。

## 実機試験の手順

### 準備

1. 自動検証を通したReleaseを使い、他のプレーヤーを終了する。再生機器の音量を下げ、利用するx64 ASIOドライバーを指定する。
2. `scripts/check-asio-drivers.ps1 -Json` で登録を確認し、対象のCLSIDを手元の設定へ記入する。このコマンドはドライバーをロードしない。
3. 試験前のレート、バッファー、接続、出力ペアを控える。製品が変更するサンプルレートと、ドライバーが保持する推奨幅を別の値として扱う。
4. 対象コミット、EXEのSHA-256、OSビルド、ドライバーの版、入力形式・レート・長さ、操作、結果を記録する。機材識別情報・個人パス・音源名を含む実行記録は `private/results/` に置き、公開文書へ転記しない。

```powershell
$driverClsid = Read-Host 'ASIO driver CLSID'
.\out\x64\Release\wavplay_tests.exe --probe-asio $driverClsid
```

照会を2回行い、現在レート、出力型、バッファー範囲・粒度の取得と解放・再オープンを確認する。失敗した場合は操作とエラーを記録する。音声を出す診断は、再生の準備を整えてから別に実行する。

### 操作と合否

| 確認項目 | 判定条件 |
|---|---|
| 機器未設定と設定後の起動 | 未設定ではNO DEVICEと案内を表示しPlayを無効にする。有効な機器設定で再起動すると指定機器・出力ペアで停止状態になる。不正値や登録欠落では代替機器を開かない |
| 左右とモノ | 左右を識別できる低レベルのステレオ音源とモノ音源で、指定した出力ペアとモノの両側出力を確認する。複数ペアを使える機器はOutputPairを変更して再起動する |
| レート | 製品が対応する44.1／48／88.2／96／176.4／192／352.8／384 kHzについて機器の受理・拒否を確認する。受理したレートでは各10秒以上再生し、表示と出音を確認する。機器非対応と、対応を報告した後の切替失敗・表示不一致・無音を区別する |
| BufferSize | 0／未設定はそのレートの現在の推奨幅、対応する正値は指定幅になる。不正値や範囲外では代替幅を使わず拒否する。実幅・範囲・粒度・ブロック時間を画面と照合する |
| StartSilence | 未設定の100 msと0～1000 msの指定、ブロック単位の切上げ、不正値の拒否を確認する。再生開始・再開・異レート曲間の先頭に適用し、同一レート曲間には追加しない |
| Pause／Resume・Stop／Play | 再開位置と左右を確認する。Pause後は未再生位置から、Stop後は選択曲の先頭から再生する。クリックの許容範囲と、欠落・重複・再生中の歪みを区別する |
| 曲間 | 同一レートで連続する波形を分割した音源で、曲間の途切れを確認する。異レートでは切替後の表示と出音を確認し、非対応の次曲はその項目で停止する |
| reset・幅変更通知 | 発生させられる通知で、停止・同じ機器の再初期化・位置0での停止待機を確認する。自動再生せず、起動時の設定を保持する。実機で発生させられない通知は未実施とし、模擬ASIOの確認と区別する |
| Close・再オープン | 停止・解放と、変更した元レートへの復元を確認する。推奨幅は独立に記録し、前後差だけで失敗としない。別の診断で条件を戻す場合は、その操作前後を製品終了直後と区別する |
| ウィンドウと設定保存 | 移動・リサイズ・最大化・最小化後の終了と再起動、モニター構成変更での位置補正を確認する。起動後のINI手編集・コメントを保持し、保存失敗では既存設定を壊さずエラーを表示する |
| 長時間と電源 | 受理した最高レートと安定して使える最小幅で30分再生し、途切れ・異常停止・ハングを確認する。表示中と最小化を分け、自動スリープ抑止・画面消灯・停止後の抑止解除も確認する |

各項目を合格・失敗・未実施で記録する。表示や音が出たことだけから、物理出力の全サンプル一致や一般的な音質改善を認定しない。サンプル一致は模擬ASIOの全バイト照合、物理出力の測定、聴感の観測をそれぞれ区別する。

実機用のWAVは自分で用意し、形式・レート・長さ・期待する左右の信号を記録する。機器が対応する出力型・精度で使用し、音源のフェードや末尾無音はWAVの内容として扱う。自動試験内で生成するデータは模擬ASIOの照合用であり、実機用音源の配布や実機の確認を代替しない。
